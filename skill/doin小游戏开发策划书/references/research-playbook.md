# 调研方法论（Research Playbook）

> 目标：在 3–5 次搜索内拿到足够支撑策划判断的竞品事实，**不要**做成长篇行业报告。
> 调研是为了"找准差异化"，不是为了引用来源堆砌。

## 1 · 何时搜、搜什么

用户给的一句话通常形如："X 游戏，传统玩法，Y 风格，Z 创新"。按以下顺序判断：

1. **是否为知名经典玩法**（俄罗斯方块/贪吃蛇/扫雷/数独/五子棋/2048/推箱子/打砖块…）？
   - 是 → 不搜"这是什么"，直接搜"近年创新变体 / 现代 web 版做得好的例子"。
2. **是否为陌生品类**（如"肉鸽卡牌构筑""时间管理经营""节奏音游"）？
   - 是 → 先搜 1 组该品类定义与代表作，再搜 web/移动端变体。
3. **用户提到的"创新"关键词**（交互创新/双人/物理/roguelike…）→ 针对性搜。

## 2 · 搜索 query 配方（每次最多 3 组，并行发）

按优先级挑 2–3 组，**不要**把 6 组全发：

| 目的 | query 模板（中英各挑一个） |
|---|---|
| 找 web/页面对标 | `"<genre> game poki.com popular"` / `"<genre> browser game 2024"` |
| 找移动端口碑作 | `best <genre> mobile game reddit` / `<genre> 创新玩法 手游` |
| 找现代变体 | `modern take on <classic> game mechanics` / `<classic> game reimagined` |
| 找差异化灵感 | `innovative <genre> mechanics indie` / `<genre> roguelike twist` |

- 用 `general_search`，snippet mode 用 `minimum` 就够——只要竞品名、核心机制、一句话亮点。
- 摘要够了就不要 `web.fetch` 全文；除非某个对标产品的机制描述确实关键且摘要不全。
- **不要**为了凑来源而搜中文泛泛文章；英文 itch.io / Reddit / GDC talk 摘要信噪比更高。

## 3 · 竞品表怎么填

调研结果直接填进 PRD 模板第 1 章的对标表，每行必须有：

- **借鉴点**：具体到"它的什么设计我要抄"（不是"它画面好看"）。
- **避坑点**：具体到"它的什么设计我不要重复"（不是"它太氪"）。
- 选 3–5 个对标即可，**不要**列 10 个——列越多越没结论。

## 4 · 判断差异化的三个追问

搜完后，在落笔前自问：

1. **如果我只做"传统玩法 + 精美 UI"，能不能和这个对标产品拉开差距？**
   不能 → 必须在第 3.2 节写出至少一个真创新机制。
2. **这个创新机制在工程上是 plain 静态能做的吗？**
   不是（需要服务器/AI 推理/3D 引擎）→ 降级或砍掉，写进"v1.1+ 不做"。
3. **它和门户现有 14 款比，玩家为什么玩这个而不是那个？**
   答不出 → 回到第 1 章重新定位。

## 5 · 调研的边界

- 不要去爬 Poki/CrazyGames 全站榜单；读 3 个摘要足够形成判断。
- 不要调研商业化、广告变现、DAU 预估——这是单人静态门户，不涉及。
- 不要引用具体下载量/收入数字当决策依据（除非来源明确且新）；用"口碑/同类密度"定性判断。
- 找不到好对标时，**直说"该品类在 web 端少有出彩变体，这本身就是机会"**，不要硬凑。
