\====================

二、DOIN 架构与交付边界

\====================

DOIN.WIN 是静态网页游戏门户，每款游戏均存放在独立子目录内：



* 游戏目录：`games/<slug>/`

* 本地调试访问路径：`/games/<slug>/`

* 线上实际访问路径：`/<slug>/`

【交付范围限制】

你只负责开发此独立小游戏，严格仅生成：

`games/<slug>/`

目录内部的完整文件。

严禁修改或生成门户外层文件，包括但不限于：



* 根目录 `index.html`

* `games.json`

* 根目录 `package.json`

* GitHub Actions 工作流

* `dist/`

* 部署脚本

* 站点级 CSS、JS 或其他门户文件

games.json 登记、封面制作、根测试脚本、机器验收、构建、部署和发布均由门户方负责。

【路径引用规范与唯一例外】



1. 所有本地资源引用与模块 import 必须使用严格的相对路径，例如：

   `css/style.css`

   `js/main.mjs`

   `favicon.svg`

   `./engine.mjs?v=dev`

2. 严禁在游戏内部使用以下绝对路径：

   `/games/<slug>/`

   `/<slug>/`

   `C:\...`

   `file://...`

3. HTML 中的本地 CSS 和 JS 引用必须保留 `?v=dev`：

   `href="css/style.css?v=dev"`

   `src="js/main.mjs?v=dev"`

4. JS 文件之间的本地 ES Module import 也必须保留 `?v=dev`：

   `import { createState } from "./engine.mjs?v=dev";`

5. 【唯一绝对路径例外】

   页面顶部或游戏工具菜单中的 "返回游戏门户首页" 链接，必须使用：

   `href="/"`

   不得使用容易错位的相对路径跳出游戏目录。

三、渲染策略与自包含规范

\====================

【双轨渲染分工：适合时优先】



* Canvas 2D / WebGL / Three.js：

  适用于连续运动、粒子、物理碰撞、动作、视差、复杂矢量动画、3D 场景或高频重绘。

* DOM / CSS：

  适用于文字解谜、离散棋盘、益智卡牌、网格、菜单和偏静态轻交互玩法。

* 所有 HUD、按钮、菜单、弹窗、语言切换、玩法说明和可读文本必须保留在语义化 DOM 层。

* 不得在 Canvas 内手工绘制表单、长文本、菜单或需要无障碍阅读的内容。

* 不得在复杂连续运动场景中滥用大量 DOM 节点。

* 本游戏 {{填入：玩法类别}} 属于 {{填入：离散网格玩法 / 连续运动玩法…}}，默认优先使用

  {{填入：DOM/CSS Grid 或 Canvas 2D 的裁决结论}}。

* 如使用 Canvas，可将棋盘、路径、背景动效和完成特效绘制在 Canvas 中，但键盘操作、

  按钮、说明和 HUD 仍必须有 DOM 语义支持。

【游戏舞台布局要求】

桌面端必须像一个完整的宽屏游戏页面，而不是手机网页套在桌面中央。

必须遵守：



* 游戏舞台优先占据浏览器主要可视区域

* 桌面端使用宽屏、舒展的布局

* 游戏区域、HUD 和操作按钮应集中在舞台附近

* 可以有紧凑的游戏工具栏、HUD 或返回按钮

* 不得制作传统门户网站式的大页头、营销文案区和页尾

* 不得把整个游戏限制成窄窄的手机屏幕样式

* 不得在桌面端出现大面积黑边、手机外壳、竖屏模拟框或生硬的居中黑色容器

* 不得把页面整体锁定为 9:16 手机比例

* 棋盘本身可以保持正方形或固定比例，但整个页面不应模拟手机竖屏

* 桌面宽屏下应充分利用可用空间，视觉上更像打开了一款游戏

* 移动端仍要自然收缩，保证 390px 宽视口不横向溢出

* 不得依赖 hover 才能完成核心操作

【零外链资源与自包含底线】



* 使用原生 HTML5、CSS3 和 JavaScript ES Modules

* 默认零依赖、零构建、零 npm

* 严禁外部 CDN、远程 API、在线字体和远程图片

* 只使用系统字体栈，不加载 WebFont

* 禁止使用 `alert()` 作为游戏反馈

* 普通反馈使用页面内 DOM toast、提示区或结算面板

* 破坏性操作（例如清空存档）可以使用 `confirm()`，其他交互不得依赖原生模态框

【Three.js 可选规范】

Three.js 只能作为受控的可选技术，不是默认技术栈。

只有在游戏确实需要以下能力时才允许使用：



* 真实 3D 场景

* 摄像机和空间层次

* 光照和材质

* 3D 模型

* 空间粒子

* WebGL 后处理

* 明确依赖三维表现才能成立的玩法

必须遵守：



* 简单 2D、棋盘、网格和文字玩法不得为了 "看起来高级" 强行使用 Three.js

* 不得让大模型临时伪造、手写或截断 Three.js 源码

* 不得从 CDN、远程 URL 或 npm 加载 Three.js

* 只能引用项目方已经预置的本地文件：

  `games/<slug>/libs/three.module.js`

* 如果项目方没有提供该文件，必须改用原生 Canvas/DOM，不得留下未满足的依赖

* Three.js 只能放在 `render.mjs` 或其他视觉模块中

* `engine.mjs` 不得 import Three.js，也不得接触 DOM、Canvas 或 WebGL

* Three.js 本地 import 必须使用相对路径和 `?v=dev`

* 必须处理 DPR、ResizeObserver、逻辑尺寸与物理尺寸同步

* `setPixelRatio()` 必须设置合理上限，避免高分屏显存和性能异常

* 必须处理 WebGL 不可用或 context loss 的情况

* 重玩、切换关卡或销毁场景时释放 geometry、material、texture、renderer 等资源

【音效发生器】

{{填入：是否包含音效（默认包含）}}：



* 必须使用原生 Web Audio API

* 使用振荡器、合成器或程序化音效

* 在用户首次手势（例如 "开始游戏" 按钮）时解锁 AudioContext

* 静音时静默降级

* 浏览器不支持 Web Audio 时不得抛错

* 严禁外部音频文件

如果任务参数明确不需要音效，可以省略 `audio.mjs`。

【视觉图元】



* 优先使用 CSS、内联 SVG、Canvas 或 Three.js 实时绘制

* 严禁引入外部位图

* 禁止使用外部图片 URL

* 不制作带文字、logo 或水印的游戏内素材

四、代码组织与模块架构

\====================

代码需在 `games/<slug>/` 内清晰模块化，遵循单向数据流和职责隔离。

严禁为了凑目录生成空文件、透传包装层或没有实际作用的模块。

推荐结构如下，按需裁剪：



* `index.html`


  * 仅承载语义化标记和资源挂载

  * 不得内联大段 CSS

  * 不得内联游戏实现脚本

  * 必须包含正确的 `<!DOCTYPE html>`

  * 必须包含 `html lang`

  * 必须包含 viewport

  * 必须包含 meta description

  * 必须包含 favicon 相对链接

  * 必须包含 `<noscript>` 兜底

  * 必须包含 `<a href="/">` 返回门户链接

  * 必须包含游戏舞台、HUD、按钮和说明挂载节点

  * 不得制作传统网站式页头和页尾

* `favicon.svg`


  * 游戏独立图标

  * 文件内容为自包含 SVG 标记

  * 不得依赖外部资源

* `css/style.css`


  * 响应式布局

  * 宽屏桌面游戏舞台

  * 390px 移动端适配

  * 系统字体栈

  * 操作按钮和 HUD 样式

  * `prefers-reduced-motion` 降级

  * 页面内微动效

  * 不得把桌面端设计成手机竖屏壳

* `js/engine.mjs`


  * 核心纯规则

  * 规则模型

  * 状态转移

  * 路径合法性

  * 碰撞或边界判定（如适用）

  * 不依赖 DOM、Canvas、WebGL、Three.js、window、document、localStorage

  * 纯函数或数据化实现，方便 Node 单测

* `js/game.mjs`


  * 按需提供主循环

  * 连续动画使用 `requestAnimationFrame`

  * 使用 Delta Time

  * 管理 Ready / Playing / Paused / GameOver 等流程状态

  * 不直接操作 DOM

* `js/render.mjs`


  * 按需提供 Canvas 2D、WebGL 或 Three.js 渲染

  * 只读 engine state

  * 负责 DPR、ResizeObserver、绘制、粒子和视觉生命周期

  * 不得私自修改核心规则状态

* `js/ui.mjs`


  * 按需提供 DOM HUD

  * 管理按钮、菜单、弹窗、toast

  * 管理语言切换显示

  * 管理键盘焦点

  * 负责可访问性属性和文本更新

* `js/audio.mjs`


  * 按需提供 Web Audio 程序化音效

  * 处理解锁、静音和异常降级

* `js/score.mjs`


  * 按需提供唯一计分规则

  * 负责分数计算和最高分判定

  * UI 不得重复实现计分公式

* `js/storage.mjs`


  * 唯一本地持久化封装

  * 负责读取、写入、normalize 和内存降级

* `js/i18n.mjs`


  * 多语言字典

  * 统一语言探测、加载、保存和格式化 API

* `js/main.mjs`


  * 入口装配

  * 绑定按钮、Pointer、Touch、Mouse、Keyboard 和 ResizeObserver

  * 初始化 i18n、storage、audio、game、render、ui

  * 不得绕过 engine 直接修改游戏规则

五、系统协同规范

\====================

【统一 i18n API】

全局语言 Key 必须使用：

`doin.lang`

语言探测优先级：



1. 已保存的 `doin.lang`

2. 浏览器 `navigator.language`

3. 默认英文

语言判断：



* `zh*` 使用中文

* 其他语言回退至英文

`js/i18n.mjs` 必须导出：



* `LOCALES`

* `LANG_KEY`

* `DEFAULT_LOCALE`

* `isLocale`

* `strings`

* `format`

* `detectLocale`

* `loadLocale`

* `saveLocale`

* `htmlLang`

要求：



* 中英文键值对必须完整对齐

* 不得存在空字符串或 `undefined`

* 语言切换后调用 `saveLocale(locale)`

* 然后完整重渲染或刷新页面

* 语言按钮必须有清晰的 aria-label

* 语言切换控件必须支持键盘操作

【数据持久化与 Normalize】

存档 Key 必须使用：

`doin.<slug>.v1`

如确实需要分域，可使用：

`doin.<slug>.<domain>.v1`

要求：



* 所有 localStorage 读写只能集中在 `storage.mjs`

* 所有读取、写入和 JSON 解析必须使用 `try/catch`

* JSON.parse 的结果不得直接信任

* 所有字段必须经过严格类型检查

* 所有数值必须检查 NaN、Infinity、负数和边界

* 存档缺失、损坏、版本不兼容或存储不可用时，回退到模块内存默认值

* localStorage 不可用时仍必须能够正常开始游戏

* 不得因为隐私模式、配额限制或坏存档导致白屏

六、画布、交互质量与状态底线

\====================

【Canvas / WebGL 规范】

如果启用 Canvas 或 WebGL：



* 根据 `window.devicePixelRatio` 设置物理分辨率

* CSS 维持逻辑尺寸

* 使用 `ResizeObserver` 或 resize 事件同步尺寸

* 指针、触摸和鼠标坐标必须通过 `getBoundingClientRect()` 正确换算

* 不得假设 CSS 尺寸等于 Canvas 物理像素

* 连续运动必须基于 Delta Time

* 每帧 dt 必须设置合理上限，例如 `Math.min(dt, 0.1)`

* 复杂物理使用固定时间步累计更新

* 浏览器后台恢复后不得出现瞬移、穿模或速度异常

* 必须适配移动端触摸

* 必须适配桌面端鼠标

* 核心操作不得依赖 hover

【键盘与可访问性】



* 核心玩法必须提供与规则匹配的键盘操作

* 棋盘格、按钮和菜单必须有清晰焦点状态

* 需要时使用 aria-label、role、aria-live 等语义

* HUD 和结算文本必须能被屏幕阅读器读取

* Canvas 只负责视觉时，必须提供 DOM 操作入口或等价键盘入口

* 不能把关键玩法信息只画在 Canvas 内而没有文本或语义替代

【规则执行与状态安全】



* 任何被 engine 判定为合法的用户操作必须完整执行

* game、事件处理器、render 和 ui 层不得再次拦截、吞掉或伪装合法操作

* 渲染结果必须始终来自最新 engine state

* render 不得维护与 engine 冲突的规则状态

* Paused、GameOver 或其他不接受玩法输入的状态下，输入必须安全 no-op

* no-op 不得抛错

* 终止状态操作不得改变规则状态

* 若有随机逻辑，必须支持种子注入（PRNG）

* 解谜、固定关卡、发牌和路径生成必须保证可通关

* 挑战类玩法应保证数值增长平滑、可控，不制造系统性不可恢复死局

* 随机生成必须可以通过固定种子稳定复现

【视口与页面布局】



* 390px 宽移动端不得横向溢出

* 桌面端必须是宽屏游戏舞台

* 不得把整个桌面页面做成手机竖屏模拟

* 不得出现大面积黑边或生硬的竖屏容器

* 棋盘可以是正方形

* 桌面端按钮和 HUD 应集中在游戏区域附近

* 不得使用传统营销页、页头、页尾或大段说明占据主要游戏区域

* 必须适配：

  `@media (prefers-reduced-motion: reduce)`

* 关闭减少动效后，核心玩法和状态推进仍必须正常

* 只能减少装饰动画、粒子、震动和过渡，不得改变规则结果

\====================

八、代码生成与交付协议

\====================

【文件标识规范】

每一个独立代码块的首行，必须统一使用单行注释声明相对于项目根目录的完整路径：



```
// filepath: games/\<slug>/path/to/filename.ext
```

该标记必须位于代码块内，由插件识别并在落盘时移除，不属于最终文件内容。

无论文件是 HTML、CSS、JS、MJS 还是 SVG，都必须使用该格式。

【完整性承诺】



* 必须输出生产级完整代码

* 禁止 `...`

* 禁止 "同上"

* 禁止只输出 diff

* 禁止 `// TODO`

* 禁止伪代码

* 禁止截断逻辑

* 禁止省略必要模块

* 除 filepath 标记外，不得使用会导致文件内容不完整的占位注释

【防止接口漂移】



* 输出第 1 轮前，先在内部规划全部文件

* 先确定最终 slug

* 先规划全部 DOM id、按钮 id、模块导出接口和事件命名

* 后续轮次必须严格复用第 1 轮已经确定的 DOM id 和接口

* 如果后续发现必须修改前面已经输出的文件，必须重新完整输出该文件

* 禁止只给修改片段

【三轮交付流程】

严格分三轮交付，每一轮只在完整文件边界处结束。

第 1 轮：



* `index.html`

* `favicon.svg`

* `css/style.css`

第 2 轮：



* `js/` 目录下全部实际需要的逻辑、渲染、UI、音效、存储和语言模块

第 3 轮：



* `tests/engine.test.mjs`

* `tests/storage.test.mjs`

* `tests/i18n.test.mjs`

* `tests/markup.test.mjs`

输出完当前轮次后，主动暂停并等待指令。

如果某个文件单次回复容量不足，必须在该文件开始前暂停，并提示：

"输入【继续】输出下一文件"。

【最终交付核对】

第 3 轮完成时，必须附带人工核对清单，逐项确认：



* 已确定并统一使用最终 slug

* 所有 import 的相对文件均已实际输出

* 所有 import 路径与文件名完全吻合

* 所有本地 CSS、JS 和 import 均保留 `?v=dev`

* `index.html` 中的容器 ID、按钮 ID 与 JS 选择器完全闭合

* 桌面端是宽屏游戏舞台，不是手机竖屏模拟

* 移动端 390px 不横向溢出

* 中英双语键值对 100% 对齐

* 没有 undefined 或空字符串文案

* 存档 Key 使用 `doin.<slug>.v1`

* localStorage 经过 try/catch 和 normalize

* 合法 engine 操作都能执行

* 终止状态操作是安全 no-op

* `prefers-reduced-motion` 已覆盖

* 没有 CDN、外链字体、远程图片或远程 API

* 测试文件按 Node.js 原生测试规范编写

* 如果没有真实运行环境，只能说明 "已按规范编写，未在本地实际运行"，不得虚假声称测试通过

* 外部 AI 只交付了 `games/<slug>/` 内文件，没有修改门户文件
