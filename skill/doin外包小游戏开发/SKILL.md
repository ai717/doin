# DOIN 小游戏外包制作

把用户"想做 XX 游戏"的诉求，变成一份可直接外发给 AI 承接方、读完就能动工的
完整外包任务书（生产级规格），必要时亲自以承接方身份按任务书完成三轮交付。

## 何时读哪个 reference

开工前按顺序读：

1. **必读** `references/outsource-spec-template.md` —— 外包任务书完整模板（八节），
   唯一规格基准。所有参数填充与文件产出都必须对齐它。
2. **按需** 读 DOIN 项目根 `AGENTS.md`（§4.1 协作边界）与 `docs/GAME-SPEC.md`
   （T1/T2 验收口径）：承接方无运行环境时的自查要求、外发时该贴哪些正文。

## 工作流

### 1 · 解析需求 → 提取任务参数（不搜东西，先想清楚）

从用户诉求提取四要素：

- **游戏名称**：中文名 + 一句话玩法（如"一笔画完：一笔走完所有格子，不能重复"）。
- **核心玩法**：逐条写成"引擎可建模"的明确设计——玩家做什么 / 鼠标触摸键盘如何操作 /
  主操作（路径）如何开始、移动、结束 / 是否允许撤回、重置、重新开始 / 完成条件 /
  失败条件 / 是否多关卡 / 棋盘或关卡如何递进 / 单局时长 / 计分规则 /
  是否有步数、时间或星级 / **经典对标与算法健全性（必须对标经典成熟规则，随机关卡必须从数学上证明或通过求解器保证 100% 可解，杜绝死局）**。
- **视觉方向与桌面美学**：主题、配色、氛围、背景、粒子、完成特效自定；
  **桌面端必须采用双栏/宽屏沉浸游戏舞台（拒绝简陋死板单列拉伸），主舞台居中或居左，右侧/侧边集成游戏化 HUD（徽章化记分、关卡匾额、实体触感按键），背景带环境光晕氛围与微质感**。
- **必含功能**：默认全量（开始/暂停继续/重玩/结算/关卡进度/步数时间分数/音效开关/
  中英切换/最高分存档/玩法说明/返回首页/鼠标+触摸+键盘）。

玩法描述模糊时给建议值并标注假设，**不留 TBD/占位**。

### 2 · 定 slug

- 规则：`^[a-z0-9]+(?:-[a-z0-9]+)*$`，小写 kebab-case，简单易记（如 `one-line`）。
- 给 2–3 个候选让用户拍板；用户已给则直接用；用户说"由承接方定"才在任务书里
  保留决定条款。
- **slug 一旦确定全任务书统一**：目录名、import 路径、存档 Key `doin.<slug>.v1`、
  变量命名全部对齐，禁止在最终代码里残留 `<slug>` 占位。

### 3 · 按模板填充 → 生成完整任务书

以 `references/outsource-spec-template.md` 为基准，按第一节 `{{填入:…}}` 标记
逐项填充；二至八节为 DOIN 固定契约，原样保留，只裁决标注"按玩法裁决"的条目：

- **渲染策略裁决**：离散网格/棋盘益智 → DOM/CSS Grid；连续运动/粒子/物理 → Canvas 2D。
  双轨时 HUD、按钮、菜单、说明必须留在语义化 DOM，Canvas 只画棋盘/路径/特效；
  不得为"看起来高级"强行上 Three.js。
- **键盘操作**：核心玩法必须给等价键盘操作，鼠标/触摸/键盘三通，不依赖 hover。
- **音效**：默认包含，走 Web Audio 程序化合成（首次手势解锁、静音降级）；任务明确
  说"不需要音效"才删 `audio.mjs`。
- 每节保留原文的判定规则与红线（零外链、?v=dev、`href="/"` 返回门户、
  localStorage normalize、合法操作不拦截等），一字不改。

### 4 · 落盘交付

- 默认写入 `G:\work\code\game\doin\docs\outsource\<slug>-spec.md`
  （`docs/outsource/` 不存在就先创建；文件名 slug 用小写 kebab-case）。
- 交付用 `present_files` 给出该 md；回复正文给：
  ① 一页纸摘要（游戏名 / slug / 一句话玩法 / 渲染路线 / 是否含音效）；
  ② 2–3 个待拍板开放问题（如 slug、难度递进、计分口径）；
  ③ 下一步（"确认后可直接外发给承接方；收到三轮交付后按 AGENTS.md §4.1 组装验收"）。

### 5 ·（可选）用户要求立即生产

用户明确说"直接做 / 现在就按任务书生产"时，本代理以承接方身份执行：

- 先声明最终 slug，再按任务书第八节"三轮交付协议"在
  `G:\work\code\game\doin\games\<slug>\` 内依次产出全部文件；
- 每轮只在完整文件边界结束并暂停等指令；遵守"禁止 TODO / 伪代码 / 截断 / 只给 diff"；
- 三轮完成后附最终核对清单；机器验收与组装（games.json / 封面 / 根测试 / 构建）
  仍按 AGENTS.md §4.1 由门户方执行，除非用户明确授权一并完成。

## 不做什么

- **不修改门户外层**：根 `index.html`、`games.json`、根 `package.json`、GitHub Actions
  workflow、`dist/`、部署脚本、站点级 CSS/JS 一律不碰。
- **不做 PRD 级行业调研**：玩法已明确就直接填充；玩法模糊时最多 1–2 次搜索补对标。
- **不承诺联机 / 内购 / 后端**：DOIN 是纯静态站，出现这类需求一律降级并在任务书标注。
- **不引入外部资源**：CDN、远程图片、在线字体、外部音视频文件、远程 API 一律禁止。
- **不替外部承接方写验收结论**：没有真实运行环境时只能说明"已按规范编写，未在本地
  实际运行"，不得虚假声称测试通过。

## 输出语气

任务书正文用中文撰写（i18n 英文键值对在任务书内单独给出）。语气是"可直接开工的
工程规格"：结论先行、规则写到引擎可建模、数字给具体算例，避免"可以考虑/也许/大概"
这类含糊词。
