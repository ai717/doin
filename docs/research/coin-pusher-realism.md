# 《推币机》真实感调研与差异对照

> 触发：用户反馈「整体感觉没有模拟真实的推币机」「和真实场景有差异」。
> 目的：用真实机台与同类数字游戏的实测/文献数据，定位「不像」的具体来源，给出可执行的改进清单。
> 结论口径：**只列有据可查的差异**；来源冲突处标注冲突，不取平均值假装精确。
> 撰写时间：2026-10-08 · 对应版本：`games/coin-pusher/`（斜俯视 2.5D 返工后）

---

## 0 · 结论速览

调研后可以明确：**「不像」的主因不是视角**。上一轮把俯视 2D 改成斜俯视 2.5D 是必要但不充分的——
真实机台制造「推币机感」的核心是下面五件事，当前实现**五件全缺或严重不足**：

| 排序 | 差异 | 当前 | 真实 | 影响 |
|---|---|---|---|---|
| **1** | 币堆是**单层平铺** | 物理单层圆盘，渲染靠 0.30 世界单位的假抬升 | **3~5 层**层叠，边缘常年 **10~15% 悬垂**，有「摇摇欲坠的币塔」（teetering towers） | 第一眼就不像——真实机台的视觉签名就是「币山」 |
| **2** | 币的**材质语言**像塑料按钮 | 硬边金色环 + 平涂，无偏心高光、无接触阴影、币与币完全相同 | 黄铜/锌合金，各向异性反光、滚花边缘、磨损与氧化不均 | 第二眼就不像 |
| **3** | **推板行程**只有币堆纵深的 15% | `PUSH_STROKE = 0.85 D`，币堆纵深 ≈ 5.6 D → 比值 **0.15** | 行程 15~20cm（≈6~8 倍币径），与币堆纵深比约 **0.5** | 玩起来不像：推板只是「轻轻顶一下」 |
| **4** | **推板节奏**快 2.5~4 倍 | 前推 1.2s + 回程 1.2s = 周期 2.4s → **25 次/分** | **6~10 次/分**（口径冲突，见 §2.3） | 当前像活塞泵，真实像呼吸 |
| **5** | **两侧丢币沟槽缺失** | `clampToWalls` 硬墙反弹（restitution 0.55），零损失 | 侧沟是机房优势的**主要来源**：「Coins that fall to the side are lost revenue for the player」 | 只剩「赢」没有「输」，情绪张力少一半 |

**次要但显眼**：机台上半部（推板后方 → 机顶）是大片空洞黑区，真实机台那里是奖品陈列柜 + 招牌灯箱 + 币槽；前唇读成「边框」而不是「掉币边缘 + 托盘」；宝石币是纯色蓝椭圆，与金币的圆柱体积语言不一致。

## 2 · 真实机台解剖

### 2.1 台面与几何

- **台面本体基本水平**，仅极微前倾（让币自然贴向前沿）。真正制造「斜俯视」观感的是**玻璃观察窗 + 玩家站姿**，观察俯角约 15°~30°（S5 提到的「15°」更可能是观察角而非物理坡度——两种口径在中文资料里常被混用）。
- **投币口 → 倾斜滑道 → 落点**（S6）。币不是「从天而降」，而是**沿滑道滚入**台面，落点由滑道出口与出手力度决定。
- **台面边缘与内部有挡板 / 凸起结构**（S6），作用是限制币的活动范围 + 制造复杂轨迹。**关键**：S1 指出这些结构常常是**刻意把币导向两侧沟槽**的（「Hidden ridges or slightly convex surfaces often guide coins toward the sides」）。
- 底部 **V 型收集槽 + 螺旋提升装置**（S5），把落袋币送回循环。

### 2.2 推板（Pusher Plate）

| 参数 | 真实值 | 出处 |
|---|---|---|
| 行程 | **15~20 cm**（≈ 6~8 倍币径，币径按 2.4~2.6cm 计） | S4 |
| 单程耗时 | 约 **3 s** | S4 |
| 复位抬升 | **2 cm**（回程时板体抬起，避免把币往回拖） | S4 |
| 速度特征 | 「moves forward **slowly**」（S3）；「**slow and steady** … watch their coins **inch** closer to the edge」（S2） | S3 / S2 |

**复位抬升 2cm 是一个当前完全没做的机械细节**：真实推板回程时微微抬起，所以**回程不把币往回带**；当前实现回程同样与币做碰撞约束（`clampToPusher`），币会被拖回一点。

### 2.3 推板节奏（来源冲突，需注明）

| 口径 | 次/分 | 出处 |
|---|---|---|
| 6~8 次/分 | 6~8 | 设备资料 |
| 2~3 次/分 | 2~3 | 设备资料（另一来源） |
| 由 S4 推算（3s 单程 → 6s 周期） | **10** | 专利推算 |

三口径不一致，**唯一一致的结论是「远慢于当前实现的 25 次/分」**。S3 另提到运营者可在服务菜单里**调节游戏速度**——说明速度本身是机台的可调参数，不存在唯一正确值。因此本项目应取**区间中段 10~12 次/分**，而不是去追某一个「真值」。

### 2.4 硬币堆叠

- **3~5 层**层叠，底层承受约 3 kg/cm² 压力（币重约 5~7g，密堆下逐层传递）。
- 边缘常年 **10~15% 的币悬垂**在边缘外而不掉——这是推币机最上瘾的画面。
- 存在 **「teetering towers」（摇摇欲坠的币塔）**：玩家会专门寻找这种堆，因为「physics dictates these *must* fall with minimal force」（S1）。
- 崩塌是**非线性**的：S3 描述为「unstable layers / lower support weakens over time / **sudden collapse**」→ 一次推板可能引发多枚同时掉落（cascade）。
- **摩擦是关键变量**：脏台面摩擦大，币会**互相骑过去**（ride over each other）而不是整体被推走（S1）。这说明真实机台的「币堆行为」强烈依赖表面状态，不是纯几何问题。

### 2.5 侧沟（House Edge）

S1 的表述最直接，值得整段引用：

> **Side Gutter Geometry**: This is the primary method for coin pusher house edge calculation in analog machines. Coins that fall to the side (into the operator's hopper) are **lost revenue for the player**.
>
> **Why do coins slide to the side instead of the front?** This is **intentional design**; the side gutters are the "House Edge".

也就是说：**真实推币机的「输」几乎全部发生在两侧，而不是前方。** 前方落袋是「赢」，两侧落袋是「丢」。当前实现把两侧做成硬墙，等于删掉了这台机器的全部风险机制。

### 2.6 技巧维度（S1）

> Experienced players can use "**shelf timing**" — dropping a coin exactly when the pusher is **fully extended** — to maximize the force transferred to the coin pile.

真实机台的技巧核心是**推板相位**：在推板全伸时投币，让新币立刻吃到最大推力。当前实现的 `insert()` 落点与相位无关（`DROP_GAP` 只保证币落在推板前方），**没有把「相位」变成可操作的技巧维度**。

## 3 · 同类数字游戏怎么做的

| 游戏 | 关键做法 | 可借鉴 | 应避开 |
|---|---|---|---|
| **Coin Dozer**（Game Circus） | 「board-shaking and **coin-wall** physics」——刻意做**摇台**输入与**币墙**视觉；奖励令牌掉落 + 集卡进度驱动 | **币墙**（多层堆叠的视觉主体）与**摇台**（非物理精确但手感强的即时反馈） | 3D 特效过重、抽奖化氪金 |
| **Coin Pusher Casino**（Steam） | 80+ 机台布局、多级台、巨型物品堆、玻璃柜 + 大量视觉元素；表现力靠「多机台 + 机关 + 币落槽的叮当声」 | **机台布局多样性**与**音效层**（币落槽的哗啦声是灵魂） | 内容量堆砌 |
| **Coin Pusher Pro**（Unity 模板） | 简单三键操作 + 玻璃柜完整建模 | 玻璃柜的**完整几何**（前玻璃、侧玻璃、机顶灯箱都要有） | 通用模板感 |
| **CoinDozerGame**（GitHub） | 开源实现，2D 俯视 + 单层圆盘 | 作为「技术可实现性下限」的参照 | 单层平铺的视觉 |

**共同结论**：数字同类作品能「像」的关键不在物理精度，而在 **① 币墙（多层堆叠的视觉体量）② 机台完整几何（玻璃柜/灯箱/陈列）③ 音效层**。三者当前都缺或很弱。

## 5 · 根因：为什么「感觉不像」

1. **视觉签名缺失**。推币机在人类记忆里的图像是「一坨层层叠叠、边缘悬着一排快掉下去的币山」。当前是「一张整齐排布的单层币饼」——两者在**第一眼**就分道扬镳，与视角、光照无关。
2. **机械幅度太小**。推板行程只有币堆纵深的 15%，且周期快 2.5~4 倍。结果是「高频微动」而非「低频大摆」，观众看不出推板在「推」，只看到画面在抖。
3. **风险机制被删掉**。两侧硬墙 → 玩家永远不会「失去」币 → 只有正反馈没有负反馈 → 真实机台那种「盯着币滑向侧沟」的紧张感完全没有。
4. **机台不完整**。推板后方到机顶的空洞让画面下半部（台面）与上半部（空）割裂，读成「一个带边框的板子」而不是「一台柜子」。
5. **材质是塑料不是金属**。硬边高光环是「按钮」的语言，不是「硬币」的语言。

## 6 · 改进清单

> 分级依据：**P0 = 决定「像不像」**，P1 = 结构与材质，P2 = 手感与声音。
> 每项给出落点、预期、验收方式与副作用。**建议按 P0-1 → P0-2 → P0-3 顺序单独立项**（符合 AGENTS.md「单任务原子递增」）。

### P0-1 · 推板行程与节奏（纯 engine，最易验证，收益最大）

**改动**
```js
// engine.mjs
export const PUSHER_RETRACT = 1.9;   // 原 2.8
export const PUSHER_EXTEND  = 4.6;   // 原 3.65 → 行程 2.7D ≈ 0.5 × 币堆纵深
export const PUSH_FWD_TIME  = 2.6;   // 原 1.2
export const PUSH_BACK_TIME = 2.4;   // 原 1.2 → 周期 5.0s ≈ 12 次/分
// levels.mjs
export const START_Y = 5.15;         // 原 4.15，必须 > PUSHER_EXTEND + COIN_R
```
**必须同步处理**
- 推出速度从 0.71 D/s 升到 ≈1.04 D/s → 需重调 `FRICTION`(3.0) / `RESTITUTION`(0.42) / `TIP_ACCEL`(2.6)，否则落袋频率会失控。
- `START_Y` 抬高后币堆纵深从 5.6D 缩到约 4.6D → 24 关的 `goal` 与 `coins` 需按新节奏重标定。
- 新增**回程抬升**：`plateFront` 计算时给回程段加 `lift`，回程段跳过 `clampToPusher` 的拖动分支（真实机台的 2cm 抬升）。

**验收（新增单测，必须能捕获缺陷）**
- `PUSH_STROKE / pileDepth ∈ [0.40, 0.70]`（`pileDepth = FIELD_H − START_Y`）
- `PUSH_CYCLE ∈ [4.5, 6.5]`
- `START_Y > PUSHER_EXTEND + COIN_R`
- 回程段：把一枚币贴在推板前缘，跑一个完整回程，断言其 `y` **不减小**（当前实现会减小 → 断言会红）
- 重跑 1000 步随机游走 + 同种子重放一致

**副作用**：所有关卡手感与难度整体改变 → 需重跑 `npm run test:coin-pusher`、`check-game`、CDP 冒烟。

### P0-2 · 币堆分层（engine 加字段 + render 出效果）

**方案（低成本版，不破坏确定性契约）**
- 给 `coin` 加整数 `layer ∈ {0,1,2}`，物理仍在 2D 平面求解；
- 上层币的**碰撞半径按层打折**（`r_eff = r × (1 − 0.18 × layer)`）→ 允许轻微重叠 → 视觉上自然出现「压在别人身上」；
- 质量/摩擦按层微调（上层更容易被推动），使**上层先滑落**，复现 S3 描述的「底部支撑变弱 → 突然崩塌」；
- 渲染：抬升 `layer × COIN_THICK × 1.6`，并按 layer 加投影阴影与遮挡（已用画家算法按 y 排序，只需把排序键改为 `y + layer × 0.01`）。

**为什么不做真 3D**：AGENTS.md §3.4 要求「纯函数固定步长 + 同种子逐帧一致」。真 3D 物理会引入浮点不稳定与求解器顺序依赖，直接破坏可测性。2.5D 视觉足够达成「币山」的视觉签名。

**验收**
- 断言「存在 layer ≥ 1 的币时，其屏幕 y 小于同世界坐标的 layer 0 币」且「阴影长度随 layer 单调增加」
- 断言 `layer` 分布非退化（一局内出现 ≥ 2 种层）
- 断言 1000 步随机游走后 `layer` 仍守恒在 `{0,1,2}` 且金币总数守恒

### P0-3 · 两侧丢币沟槽（恢复风险机制）

**方案**
```js
// engine.mjs
export const GUTTER = 0.55;   // 每侧沟槽宽（世界单位）
// 有效台面宽度 13D → 11.9D
```
- `clampToWalls` 改为：币进入 `x < GUTTER` 或 `x > FIELD_W − GUTTER` 后**不再反弹**，改为沿沟槽加速下滑（`vy += GUTTER_ACCEL * dt`），越过 `FIELD_H` 后落入**侧仓**；
- 侧仓落币**不计分**，发 `{ type: "lost_coin" }` 事件；
- `state.lostCount` 计入状态，结算界面显示「漏币 N 枚」——这才是真实机台的心跳读数；
- 守恒式改为 `coins + dropped + lost === initial + inserted`。

**验收**
- 断言「进入沟槽的币永不回到台面」
- 断言「沟槽落币不增加 score，但增加 lostCount」
- 随机游走 1000 步断言新守恒式成立
- 断言「沟槽关闭时（`GUTTER = 0`）预期收益高于开启时」——用同种子跑 N 局对比，证明风险机制真实生效（**这条是捕获力关键**）

**副作用**：分数曲线整体收紧 → 各关 `goal` 需下调或 `coins` 上调。

### P2-10 · shelf timing（把技巧维度做出来）

S1 指出真实技巧是「在推板**全伸时**投币」。当前 `insert()` 与相位无关。
建议：投币时按 `pusherPhase` 给新币一个**前向初速加成**（全伸位 +X%，回撤位 −Y%），并在 HUD 给一个相位指示条。
**收益**：这是把「物理还原」升级为「玩法还原」的一步，也是与同类数字游戏拉开差异的点。

## 7 · 建议的落地范围

| 轮次 | 范围 | 理由 |
|---|---|---|
| **第 3 轮** | **P0-1**（推板行程与节奏）+ **P0-2**（币堆分层） | 这两条是「一眼像不像」的决定项，且都在 `engine.mjs` 内可测；P0-1 只动 6 个常量 + 1 处逻辑，风险最低 |
| **第 4 轮** | **P0-3**（侧沟）+ P1-4（机台上半部） | 恢复风险机制 + 补全机台几何；P0-3 会改分数曲线，需重标定 24 关 |
| **第 5 轮** | P1-5/6/7（材质）+ P2-8/9（声音） | 打磨层，可批量做 |
| **可选** | P2-10（shelf timing） | 玩法升级，非「真实感」必需 |

**风险提示**
- P0-1 + P0-3 都会改变难度曲线 → 24 关的 `goal`/`coins`/`par` 需系统性重标定，不能只改常量；
- 每次改动后必须重跑：`npm run test:coin-pusher`、`node scripts/check-game.mjs coin-pusher`、CDP 真机冒烟（源码路径 + `SMOKE_DIST=1` 生产路径）、`npm run build`；
- 视觉类改动必须配**定位性断言**（不能是「同位置是不是金色」这种恒真断言），并按仓库既有做法「临时还原缺陷验一次区分力」。
