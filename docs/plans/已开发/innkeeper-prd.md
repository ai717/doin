## 1 · 创意概念与核心乐趣

- **游戏名称**：中华客栈·跑堂点菜 / Inn Master / 建议 slug：`innkeeper`（单个简短纯英文单词，符合极简命名契约）
- **一句话玩法**：跑堂添茶传菜算盘结账忙客栈
- **核心乐趣与卖点**：
  - **多桌动线的时间管理爽感**：客人一桌桌进来点菜、催茶、等结账，玩家操控跑堂小二在茶台、后厨、柜台与各桌之间穿梭——先给哪桌添茶、顺路带哪道菜、什么时候去柜台拨算盘结账，动线规划得顺，一波高峰行云流水；规划乱了，客人耐心条见红、拂袖而去，手忙脚乱本身就是笑点。
  - **江南客栈的烟火气**：青砖木桌、茶壶热气、算盘脆响、跑堂吆喝“客官您的茶来咯”，题材自带中文互联网的生活流共鸣，英文用户也能靠图标零门槛理解“端茶送菜结账”。
  - **连击与小费的正反馈**：连续快速服务触发“手脚麻利”连击、客人满意给小费、算盘结账拨珠的解压手感，让每一波客流高峰都有明确的爽点波峰。
- **核心循环**：客人入座点菜 ➔ 跑堂接单动线规划 ➔ 添茶/传菜服务 ➔ 客人用餐耐心回升 ➔ 柜台算盘结账收银 ➔ 赚银两升级工位/解锁菜品 ➔ 下一波客流。

## 2 · 经典标杆与对标参考

- **成熟标杆原型**：
  - **Diner Dash（餐厅小镇/美女餐厅）**：时间管理品类开山作——带位、点单、上菜、结账、收拾桌子的多工位动线，客人耐心条与连击小费。最受认可的是“一次点击排队执行”的动线队列与耐心条可视化。
  - **Overcooked（胡闹厨房）**：多人协作的厨房动线管理——工位分工、订单倒计时、传菜动线冲突。最成熟的是订单队列压力与工位布局对动线的影响（本作借鉴其动线思想，但为单人跑堂而非多人烹饪）。
- **我们要继承的成熟机制**：
  - 客人耐心条（等待时下降、被服务时回升，见红离店）；
  - 订单气泡（每桌头顶显示所需茶/菜图标与剩余耐心）；
  - 动线队列：点击工位/桌子即把动作排进跑堂的行动队列，角色自动沿最短路径执行，玩家专注规划顺序而非手动走路；
  - 连击与小费：连续无空档服务累计连击倍率，满意客人额外付小费；
  - 关卡目标：营业时段内赚够目标银两（及格/优秀/招牌三档）。
- **本作的独特魅力与微创新（Twist）**：
  - **全程动手的多桌多工位管理**：茶台添茶、后厨取菜、柜台算盘结账三个工位 + 4–8 张桌子，玩家全程实时点选排队、亲手拨算盘结账（结账小游戏：按账单金额拨对算盘珠数），而非放置挂机；
  - **算盘结账微操作**：结账不是点一下完事——账单显示金额，玩家要在算盘上拨出对应数字（个位/十位珠），拨对才收银，拨错重拨，为时间管理加入一个有文化特色的手感环节；
  - **江南客栈题材**：菜单是龙井茶、阳春面、东坡肉、桂花糕，客人有书生、商贾、镖师等江南市井角色，耐心与小费脾气各异。
- **品类差异化定位（类型允许重复，杜绝一模一样）**：
  - 与第 7 轮候选 **`pancake`（煎饼摊，单灶台制作链，未上架，仅作对比说明）** 的差异：`pancake` 是单灶台摊煎饼的制作链（摊面→加料→翻面→出餐的单线操作）；本作是**多桌多工位动线管理**（茶台/后厨/柜台三工位 + 多桌并行订单），核心决策是动线排序而非单品制作手法。两者品类相邻但规则模型不同；`pancake` 未上架，不在 100 款底表内，此处仅作对比说明，不构成查重冲突。
  - 与站内 **`ramen-idle`（深夜拉面屋，序号 28）** 的差异：`ramen-idle` 是放置经营（离线收益、自动营业、点升级）；本作**全程动手实时服务**，无离线收益、无自动营业，客人耐心实时流失，必须亲手排动线。
  - 与站内 **`catcafe`（迷你猫咖掌柜，序号 27）** 的差异：`catcafe` 同样是放置治愈经营；本作是高压实时时间管理，有明确的营业时段倒计时与离店失败压力，心流截然不同（治愈放置 vs 手忙脚乱）。
  - 结论：与 100 款底表比对，无规则几乎一模一样的存量游戏；同属“经营”大类但本作是底表中唯一的实时多桌动线时间管理，Twist 明确。

## 3 · 玩法规则与交互说明

- **核心规则**：
  - **盘面/场景构成**：江南客栈大堂俯视/斜俯视场景——中央或一侧为工位区（茶台、后厨窗口、柜台算盘），大堂摆 4–8 张方桌（随关卡增加），门口为客人入场点。跑堂小二 1 名（后期关卡可解锁第 2 名帮工）。
  - **玩家合法操作**：点击客人/桌子接单（把该桌需求加入行动队列）；点击茶台添茶（端茶壶）；点击后厨窗口取菜（按订单取对应菜品，托盘上限 2 件）；点击桌子送茶/上菜；点击柜台进入算盘结账（拨珠对账）；点击空桌收拾（客人离店后清理残局才能迎新客）。跑堂按队列自动寻路执行，玩家可随时插入/取消队列动作（点队列图标取消）。
  - **客人流程与判定**：客人入座→点菜（订单气泡：茶/菜组合）→耐心条下降→被添茶/上菜后耐心回升并用餐→用餐完毕到柜台等结账（或原桌招手结账）→结账完成付银两+小费离店；耐心条耗尽则拂袖离店（不付钱、扣口碑，残局仍需收拾）。
  - **胜利条件与失败条件**：营业时段（关卡时长 120–180 秒）结束时，银两达到目标即胜（分及格/优秀/招牌三档）；若离店客人达到上限（如 5 位）则提前判负（口碑崩盘）；时段结束未达及格线亦判负。判定唯一明确。
  - **容错与无死局说明**：客人生成为受控随机——生成间隔与订单复杂度按关卡曲线递增，且保证任意时刻“待服务桌数 ≤ 跑堂可达服务能力上限”（生成器做上限钳制，桌满则门口排队等待而非硬塞）；菜品与茶水无限供应（工位不缺货），不存在资源死局；跑堂寻路为网格最短路径且桌间通道恒通（布局固定保证连通），不会卡死。玩家点错队列可取消重排，容错充足。
- **操作与手感**：
  - **鼠标/触控**：全程点选驱动——点桌子/工位即排队，点队列项取消；算盘结账时点拨算盘珠（或拖动拨珠）。移动端大按钮热区，托盘与队列常驻屏幕下方。
  - **键盘快捷键**：`1–8` 快速选中对应桌号、`Q` 茶台、`W` 后厨、`E` 柜台、`P`/`Esc` 暂停；算盘结账支持数字键输入金额校验（与拨珠等价）。
  - **随时可暂停与失焦保护机制（实时性游戏必选）**：
    - *暂停/继续实体按钮*：顶栏常驻醒目的「暂停 / 继续」（Pause / Resume）按钮；
    - *暂停快捷键*：`P` 键或 `Esc` 键即时切换；
    - *暂停视觉反馈*：暂停时大堂画面冻结并展示轻量半透明覆盖层（显示「已暂停 / PAUSED」，提供「继续」、「重新开始」入口），客人耐心、营业倒计时、跑堂行动全部冻结；
    - *切后台自动暂停（Visibility Auto-Pause）*：监听 `visibilitychange`，切标签页、最小化或失焦时自动静默暂停主循环与计时器，冻结音效；
    - *静态解谜自适应*：本作是实时时间管理，不适用静态豁免，暂停为强制项。
  - **误触容错与操作缓冲**：队列动作可取消；重复点同一桌不重复入队；算盘拨错只提示重拨不扣分（仅耗时间）。
- **即开即玩与平滑选关设计（Instant Play，核心体验）**：
  - **首屏秒进对局**：打开直接进入第 1 关（午市小场，4 张桌）就绪大堂，跑堂已在柜台旁待命、首批客人已入座点菜，点桌子即可开始跑堂，**严禁全屏选关遮罩**；
  - **常驻显眼选关入口**：顶栏常驻「选关」/「模式」按钮，点击以轻量抽屉展示营业场次（午市/晚市/夜宵/庙会日）；结算面板提供「下一场」与「选关」；
  - 记忆本地进度（已解锁场次与最佳银两），下次打开直接续上次场次。
- **模式与内容编排（严禁套路化，依游戏特质定制）**：
  - **章节关卡制**：按场次分章——午市小场（4 桌、单茶单菜）→ 晚市正餐（6 桌、多菜组合）→ 夜宵摊（8 桌、急客多）→ 庙会日（8 桌+帮工解锁、订单最复杂），每章引入新客人脾气或新菜品；
  - **升级编排**：银两可升级茶台（添茶更快）、托盘（容量+1）、帮工（第 2 名跑堂自动跑简单单），升级在选关抽屉内完成，不打断对局；
  - **严禁无脑套用“无尽冲分 + 每日挑战”**：本作以场次目标银两与三档评级为核心，不设无尽与每日。
- **游戏目标与反馈体系**：
  - 核心指标：本场银两（含小费）、服务客人数、离店客人数、最高连击；每场三档评级（及格/优秀/招牌）对应三星；
  - 胜利反馈：打烊时柜台算盘噼啪汇总 + 银两入账动画，结算展示本场战绩卡。
- **双语核心词汇与数据键名规划（防英文界面夹杂中文）**：
  - 模式/场次名：午市小场 Lunch Rush / 晚市正餐 Dinner Service / 夜宵摊 Night Snacks / 庙会日 Temple Fair（数据 key 如 `shift_lunch`、`shift_fair`）；
  - 菜品名：龙井茶 Longjing Tea / 阳春面 Plain Noodles / 东坡肉 Dongpo Pork / 桂花糕 Osmanthus Cake（数据 key 如 `dish_tea`、`dish_pork`）；
  - 工位名：茶台 Tea Station / 后厨 Kitchen / 柜台 Counter / 算盘 Abacus；
  - 客人类型：书生 Scholar / 商贾 Merchant / 镖师 Escort（数据 key 如 `guest_scholar`）；
  - 数据层约束：所有菜品、客人、场次数据一律用字符串 key/id，展示层通过 i18n 获取文本，严禁裸写中文；语言切换原地热更新，严禁 `location.reload()`。

## 4 · 题材原生视窗隐喻与音色质感（拒绝抄袭雷同）

- **题材风格关键词**：江南客栈、青砖木桌、茶壶热气、算盘脆响、市井烟火。
- **专属视窗物理隐喻（严禁连环参考老项目，拒绝左右双翼套路）**：
  - 视窗形态：**客栈大堂斜俯视实景**——主舞台就是客栈大堂本身：上方是后厨窗口与茶台（工位横排），下方大堂摆方桌、门口在右下，柜台在左下带一把大算盘；顶栏是客栈招牌横匾（场次名+营业倒计时+银两），底部是跑堂的托盘与行动队列条。布局依大堂动线定制，不做左右双翼卡片。
  - 严禁照搬三栏套路，严禁四角散落浮动按钮，严禁右侧堆叠 SaaS 表单卡片；保持全站沉浸暗色底蕴，大堂用暖黄灯笼光、青砖冷灰形成江南夜色反差。
- **立体质感与渲染路线裁决**：
  - 裁决：**DOM + CSS 3D 或 Canvas 2D**（95% 优先路线）。大堂与角色用 Canvas 2D 绘制斜俯视场景与跑堂走动动画，算盘拨珠用 DOM/CSS 3D 珠子，UI/HUD 用 DOM；无真三维空间需求。
  - 不采用 Three.js；若后续确需 3D 大堂视角，必须守三条红线（零外部 3D 模型纯代码生成几何体、轻量低开销着色防发烫、所有 UI/HUD 严格在 DOM 层隔离）。
- **声效风格与材质音色规划（严禁千篇一律蜂鸣器）**：规划 6 种专属材质音效——
  1. 添茶：茶水入杯的细流声（滤波噪声+水滴 FM）；
  2. 上菜：瓷盘落桌的轻脆声（短噪声+陶瓷共振）；
  3. 算盘拨珠：木珠撞击的噼啪连响（多脉冲噪声滤波，结账解压核心）；
  4. 收银：铜钱入柜的金属叮当（失谐金属振荡）；
  5. 客人满意/小费：轻快的木鱼+铃音组合；
  6. 客人离店：椅子拖动+门帘声（摩擦噪声）。
  - 拒绝单振荡器 beep 与 C-E-G-C 琶音。
- **封面设计提案**：640×640 软胶质感，单一居中主体（端着托盘茶壶的软胶跑堂小二，旁置一把算盘），占画面 60–75%、无文字，暖黄灯笼光渐变背景。

## 5 · 战绩留存与会话流转规划（通用且平台无关）

- **通用战绩图（可选，平台无关）**：
  - 触发时机：打烊达招牌档或刷新单场银两纪录时；
  - 呈现形式：Canvas 绘制战绩卡（游戏标题、场次、银两、服务人数、最高连击、`doin.win` 链接），中英双语自适应。
