## 1 · 创意概念与核心乐趣

- **游戏名称**：滑冰推箱 / Ice Slide（副标：冰面惯性推箱 · 撞墙才停）/ 建议 slug：`ice-slide`
- **一句话玩法**：在冰封湖面上推动补给箱，人和箱子都会滑行、撞墙才停——把每只箱子推上科考站灯标，一步都不能多想。
- **核心乐趣与卖点**：
  - **滑行惯性彻底改写规划（Momentum Planning · 用户点名核心）**：普通推箱可以"推一格、歇一步"微调；冰面上**人和箱子都会滑到撞墙才停**——不能中途刹车，每个方向都是一条"单程滑道"。规划维度从"下一格"变成"整条滑道"，推理方式完全不同，**绝不是 sokoban 换皮**；
  - **撞墙才停的轨道思维（Lane Thinking）**：墙不仅是边界，更是**刹车点**——"把箱子推到这面墙前停住"是核心语法；转角库、长直道、L 形弯，每关都在训练"用墙规划动量"；
  - **求解器保证的可解脑洞（Solver-Guaranteed · 用户点名）**：每关由 BFS/IDDFS 求解器断言可解并给出**最优步数 par**——零无解、零死局、可背谱，复用平台 `sokoban` 验证基建；
  - **经典脑洞 × 极地题材（Classic × Polar）**：推箱 × 冰面是成熟的经典变体，配极地科考题材——冰晶、极光、灯标，脑洞与氛围双重满足；
  - **品类补位（Puzzle Gap）**：平台已有 `sokoban`（传统推箱）与 `klotski` 等离散益智，冰面滑行惯性推箱是全新规划维度（惯性滑行类空白）。
- **核心循环**：
  ```
  读盘面找滑道（墙=刹车点）➔ 选定方向（人与箱持续滑行）➔ 撞墙/撞箱才停（动量结算）
       ↑                                                    ↓
  箱位更新（推箱入目标灯标点亮）← 滑行结算纯函数（撞墙才停）← 位置矩阵状态推进
       ↓（所有箱入目标）
  通关（用步数 vs 最优 par）➔ 星级结算 ➔ 下一关 / 每日一局
  ```

## 2 · 经典标杆与对标参考

**经典标杆与成熟参考**：

| 标杆 | 平台/来源 | 核心机制 | 亮点 | 借鉴要素 | 避开要素 |
|---|---|---|---|---|---|
| **Sokoban（1981 Thinking Rabbit）** | 全平台 | 推箱到目标、逐个微调 | 推箱类祖师，规划与验证范式 | 关卡格式、目标点判定、BFS 可解性验证（平台 `sokoban` 已落地） | 无滑行惯性（本作核心差异） |
| **冰面推箱变体（Ice-Sokoban / 企鹅推箱）** | Web/移动 | 人箱滑行、撞墙才停 | 成熟经典变体，惯性规划的验证 | 滑行至停规则、借墙停箱语法 | 关卡偏少、无星级编排 |
| **ChuChu Rocket（SEGA 2000）** | 主机 | 网格滑行引导、轨迹规划 | 滑行引导的轨道思维标杆 | "借墙/借障碍停"的轨道规划语言 | 实时多鼠目标过重（本作回合制纯推箱） |
| **DOIN 存量 `sokoban`** | Web | BFS 可解性验证、关卡生成 | 平台既有推箱验证基建 | 关卡字符格式（`#`/空格/`$`/`.`/`@`/`*`/`+`）、BFS 死锁剪枝思想（代码因边语义不同不直接复用）、`x/sokoban/solve-levels.mjs` 的 par 实算范式 | 仓库题材与无滑行规则（本作异质） |

**我们要继承的成熟机制**：
1. **推箱目标判定（Box-on-Goal）**：所有箱子推上目标点即过关——经典推箱的胜利条件一字不省；
2. **关卡格式复用（Level Format Reuse · 用户点名）**：直接复用 `sokoban` 关卡字符格式（`#` 墙 / 空格冰面 / `$` 箱 / `.` 目标 / `@` 人 / `*` 箱在目标 / `+` 人在目标），关卡文件与解析基建零改造迁移；
3. **BFS 可解性验证（BFS Solver · 用户点名）**：冰面语义专用 BFS（状态 = 玩家位 + 箱位 bitset，每次方向一条边，层数即最优步数；复用 `sokoban` 的死锁剪枝思想）——每关断言可解并计算**最优步数**作为 par，求解器结果写入测试断言每次重跑复核；
4. **星级与步数评价（Moves & Stars）**：以"用步数 ≤ 最优 par"为星级核心——评价体系依游戏而定，绝不做无尽冲分；
5. **固定步长确定性逻辑（Deterministic Logic）**：120Hz 纯函数帧步进、种子注入（每日一局）、同种子重放一致、箱数守恒（本策划案的核心契约）。

**本作的差异化微创新（拒绝无聊照搬）**：
1. **人与箱统一滑行惯性（Unified Slide Momentum）**：人滑行 + 推箱后箱体也滑行至停——"推一下，飞一程"是冰面推箱独有的节奏；借墙停箱（转角库）成为核心语法，普通推箱的"一格一停"完全失效；
2. **雪地阻滞格（可选机制）**：少数关卡引入"雪地格"（人/箱可在其上停住），作为中后段的容错教学件——滑行与阻滞交错，规划语言更丰富（见拍板项 3）；
3. **极地科考原生视窗（Polar Station）**：冰晶湖面棋盘 + 冰脊墙 + 补给箱 + 科考站灯标 + 极光环境——与 `sokoban` 的仓库题材彻底区隔，全站无同款视窗；
4. **每日一局（Daily Slide）**：日期种子确定性选取一局冰面残局——契合平台"确定性种子每日同题"传统，每日仪式复玩（见拍板项 1）；
5. **滑行轨迹残留（Ice Trail）**：人与箱滑过留下渐隐冰晶轨迹，帮助玩家理解"这条滑道通向哪里"——惯性规划的可视化教学。

## 3 · 玩法规则与交互说明

### 3.1 场景构成（冰晶湖面棋盘，俯视 2D）
- **棋盘**：矩形网格（复用推箱关卡格式），格类型——**冰面**（滑行面）、**冰脊墙**（阻挡/刹车点）、**补给箱**（可推对象）、**科考站灯标**（目标点）、**科考员**（玩家）；
- **滑行规则**：科考员与补给箱在冰面上**持续滑行，撞墙或撞箱才停**；推箱时箱体同样滑行至停；
- **灯标（Goals）**：目标点（可多格）；箱入灯标即点亮（图标/颜色变化），全部点亮即过关；
- **雪橇托盘（HUD 容器）**：棋盘下方雪橇工具托盘——步数计数、最优 par、灯标进度、选关/重开收纳。

### 3.2 判定与规则（核心契约：撞墙才停的滑行引擎）
1. **滑行结算（Slide Resolution）**：选定方向后——
   - **科考员滑行**：沿方向逐格移动，直到前方是冰脊墙或补给箱（或棋盘边界）才停；
   - **推箱滑行**：若科考员滑行途中顶到补给箱，则箱体沿同方向继续滑行——箱体**前方**路径无墙无箱，则人箱**同步滑行**至箱体撞墙/撞箱才双双停下（科考员停在箱体最终位置的后一格）；若箱体前方即时被堵死（一格都滑不动），科考员滑到箱前相邻格即停、该步照常计数——冰面规则下**不存在"该方向无效"**，只有"滑到了但没推动"；
   - 每次操作 = 一次完整滑行结算（纯函数，逐格推进可测）；
2. **目标判定（Goal Check）**：每步结算后检测箱位——所有箱子位于灯标格即过关；箱在目标格上显示"点亮"状态（`*` 等价态）；
3. **胜负与评级（章节制）**：
   - **通关**：全部箱子入灯标；
   - **评级**：★ 通关；★★ 用步数 ≤ 最优解 × 1.3（solver 计算）；★★★ 用步数 = 最优解（完美通关）；
   - **无死局保证**：每关**初始态**由求解器断言可解（见 3.4）；玩家失误可能把箱推入死角（推箱类固有风险），由**无限次撤销**与求解器提示兜底，绝不出现"卡死只能重开"的局面；
4. **每日一局（Daily）**：日期种子确定性选取一关（同题传统），当日只此一局、错过不补。

### 3.3 模式与内容编排（拒绝套路化三件套）
- **章节关卡制（Ice Campaign，主打）**：**4 章 × 8 关 = 32 关**，评价体系 = 星级 + 用步数 vs 最优 par，绝不做无尽冲分：
  - 第 1 章·初踏冰面：小盘直道，学"撞墙才停"与借墙停箱；
  - 第 2 章·转角库：L 形弯与转角停箱，学用墙规划动量；
  - 第 3 章·双箱协作：多箱互挡与先后次序，学滑道交错；
  - 第 4 章·极地迷宫：大棋盘长滑道迷宫关，综合收官；
- **每日一局（Daily Slide）**：日期种子每日一局（随机从已校验关卡池选取），全站同日同题、可分享战绩；
- **练习场（Practice）**：任意已解锁关卡无限次重试，专注背谱与完美通关（★★★）。

### 3.4 无死局与公平保证（数学可解性 · 用户点名）
1. **求解器全量校验（Solver-Guaranteed）**：每关由冰面语义 BFS 求解器（状态 = 玩家位 + 箱位，每次方向一条边；复用 `games/sokoban` 的死锁剪枝思想）断言：
   - **可解**：存在一条合法操作序列将全部箱子推上灯标；
   - **最优步数 par**：求解器给出最短步数，关卡目标以最优解为基准（★★★ = 完美通关）；
   - 求解器结果写入测试断言，**每次重跑复核**——零无解、零死局、可背谱；
2. **滑行确定性**：滑行结算为逐格纯函数（无随机、无物理抖动），同输入必同结果；
3. **操作容错**：不可推方向、越界方向一律返回 `action: null` 静默忽略（不惩罚、无 `alert()`）；任意局面都有明确可读的合法方向集；
4. **求解器提示（Solver Hint）**：运行时可从任意当前局面（初始局或游戏中局）求解最优下一步；死局态（箱入死角等）明确返回无解，UI 提示"撤销或重开"，绝不误报可解；触发状态数保险丝时静默不提示；
5. **确定性契约**：每日一局选关、随机种子全部确定性；同种子 + 同输入序列逐帧一致；≥1000 步随机方向游走（状态机不崩、箱数守恒、滑行至停正确、目标判定正确）。

> **关卡生成与 par 实算流程（2026-10-19 实测结论）**：32 关一律采用**受控走录**构造——先放置箱子，再随机走录 N 步（人箱混合演化），**终局箱位即灯标**，构造上保证可解（走录序列即一条合法解）；**严禁随机撒灯标**（实测随机灯标 24/24 无解）。生成后由求解器实算最优 par 写回关卡数据，并写入测试断言每次重跑复核。求解器性能实测充足：14×12 盘面 / 6 箱 / 400 步走录的最坏样本仅 600 状态 / 19ms，纯 BFS 即可，无需启发式或近似算法。

### 3.5 操作与手感（键鼠触全通 + 输入缓冲）
- **桌面鼠标（主路径）**：
  - **方向滑行**：按住左键向四个方向**拖拽滑动** = 沿该方向滑行（拖拽即动量，配合"滑行"手感）；点击棋盘四向边缘箭头 = 点选方向滑行；
  - **撤销**：`Ctrl+Z` 或点击雪橇托盘"撤销"（快照栈，无限次，符合推箱手感）；`R` = 重开本关；
  - Input Buffer：方向操作 60ms 窗口接受，连点不吞指令；滑行中锁输入（滑行结算期间不可再操作）；
- **键盘**：`↑↓←→`（或 `WASD`）= 方向滑行（长按 = 连续朝同一方向，撞停后再按无效）；`U` = 撤销，`R` = 重开，`Esc` = 暂停/退回弹层；
- **移动端（触控）**：向四向**滑动** = 沿该方向滑行（滑动方向与游戏内滑行同构，手感统一）；屏幕撤销/重开按钮；底部预留 `padding-bottom: max(68px, calc(16px + env(safe-area-inset-bottom)))` 广告安全避让区，绝不遮挡滑行操作区；
- **手感调优**：滑行中科考员拖出冰晶尾迹（渐隐），撞墙瞬间"咚" + 冰晶迸溅；箱入灯标"叮铃"点亮；步数计数与最优 par 并排显示（`步数 / 最优`），接近最优时 par 徽章柔光增强（无边界径向柔光，禁硬边描边圈）。

## 4 · 题材原生视窗隐喻与音色质感（拒绝抄袭雷同）

### 4.1 题材风格关键词
**极地冰面推箱工坊（Polar Ice Station）**、冰晶湖面、冰脊墙、补给箱、科考站灯标、极光天空、雪花微尘、极地黄昏。

### 4.2 专属视窗物理隐喻（严禁左右双翼模版）
本作不是"网页里嵌个推箱子"，而是一片**极地黄昏里的冰封湖面作业区**：

1. **冰湖即全部**：棋盘是冰封湖面作业区——冰脊墙、补给箱、科考站灯标、雪橇托盘操作台全部是极地场景的原生元素，**绝无四角散落浮动按钮、绝无右侧白底 SaaS 卡片堆**；与 `sokoban` 的仓库题材彻底区隔；
2. **滑行质感**：科考员与补给箱滑过拖出**渐隐冰晶轨迹**（惯性规划的可视化教学）；撞墙瞬间冰晶迸溅；灯标点亮由暗转亮 + 极光色柔光（无边界径向柔光，禁硬边描边圈）；
3. **极光环境**：极地黄昏 + 极光天空（慢速流动）+ 雪花微尘粒子，拒绝死黑/死白大平铺；返回、音效、语言收纳进科考站顶框一体化状态条；
4. **移动端（≤768px）**：棋盘全宽撑满、雪橇托盘收折为棋盘下木质工具条，底部严格预留广告安全避让区，绝不遮挡滑行操作区。

### 4.3 立体质感与渲染路线裁决
- **裁决：纯 Canvas 2D 冰面棋盘舞台 + DOM/CSS 3D 极地场景框体**（不做 Three.js）：
  - 冰晶棋盘、科考员/补给箱、冰晶轨迹、雪花粒子、极光流动 → Canvas 2D（冰面反射 + 径向光影），120fps 秒开零发热；
  - 极地场景立体感（冰脊厚度、科考站仪表、雪橇托盘、极光光晕）→ 语义 DOM + CSS 3D（`perspective` / `transform`），HUD/记分/弹层全部严格留在 DOM 层；
  - 理由：矩形网格为平面二维结构，俯视 2D 即可完整表达，无真 3D 视角需求，Three.js 无必要。

### 4.4 声效风格与材质音色规划（WebAudio 纯程序化合成，零外部音频文件）
| # | 事件 | 材质音色方案 | 合成手法 |
|---|---|---|---|
| 1 | **冰面滑行（Slide）** | 冰面摩擦"唰——"（长滑音，本作签名音） | 噪声缓冲 + 高频带通 sweep，滑行距离越长音越高 |
| 2 | **撞墙停（Hit Wall）** | 冰面撞击"咚" + 冰晶脆响 | 低频木响 + 高频冰晶瞬态（双段） |
| 3 | **推箱滑行（Push Slide）** | 补给箱滑动"咕噜" | 噪声低频 + 冰摩擦 sweep，比人滑更沉 |
| 4 | **箱入灯标（Box on Goal）** | 科考站灯标点亮"叮铃" | FM 编钟/铃音短音，温暖明亮 |
| 5 | **通关（Win）** | 极光闪烁大七和弦 + 风声收束 | FM 编钟上行琶音 + 噪声低频收尾 |
| 6 | **极地氛围（Ambient）** | 极地风声 + 雪花微响 | 噪声 LFO 低通（风声）+ 短噪声瞬态（雪花），轻微 |

> 严禁单调单振荡器 beep 或 C-E-G-C 琶音；音效全部程序化合成，静音或不支持时静默降级。

### 4.5 封面设计提案（遵循 `docs/COVER-STYLE.md`）
- **尺寸与格式**：640×640 纯 WebP，**零文字**；
- **主体构图**：单一居中主体，占画面 65%~70%——**一枚 3D 软胶木纹补给箱**在深蓝冰面上滑行、身后拖出渐隐冰晶轨迹，前方一道冰脊墙正待撞击，远处一盏科考站灯标发出极光色光点；
- **背景与氛围**：深蓝冰原至极光紫绿的平滑径向渐变背景 + 雪花微尘与虚焦光斑，冰面反射与软胶质感饱满温润——一眼传达"冰面滑行推箱"。
