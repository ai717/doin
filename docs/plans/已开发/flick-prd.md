## 1 · 创意概念与核心乐趣

- **游戏名称**：双人指弹飞棋 / Flick Duel · Two-Player Finger Flick / slug：`flick`（单个简短纯英文单词）
- **一句话玩法**：蓄力弹射棋子穿过中线小孔，清空半场胜。（19 字）
- **核心乐趣与卖点**：
  - **瞄准 + 力度控制的弹射手感**：玩家按住自己半场的棋子向后拉、蓄力、松手，棋子像被手指弹出去一样滑向中线——拉多远、用多大力、角度偏几度，全在指尖。弹得轻了够不着孔，弹得重了撞墙反弹回来，力道拿捏的微妙感就是核心乐趣；
  - **穿孔过线的爽感**：棋子精准穿过中线小孔滑进对方半场的瞬间，有「过线得分」的干脆反馈；对方棋子堆在自己半场时，还能顺手撞开对方的棋子、借力打力；
  - **同屏双人的桌面热闹感**：两个人坐在同一块屏幕两端，各自弹各自的棋子，不用联网、不用轮流等，弹射回合交替进行，节奏像真实桌面指弹棋一样你来我往。
- **核心循环**：瞄准蓄力 ➔ 松手弹射 ➔ 棋子滑行/穿孔/撞击 ➔ 轮到对方弹射 ➔ 先清空自己半场一方获胜 ➔ 再来一局。

## 2 · 经典标杆与对标参考

- **成熟标杆原型**：
  - **指弹棋/弹棋（Flick Chess / Tabletop flick games）**：桌面上手指弹棋子过线的经典玩法，成熟之处在于「拉弓式蓄力 + 方向瞄准」的操作模型与棋子滑动摩擦、碰撞反弹的物理手感；
  - **桌上弹射对决类 web 小游戏**（Poki 等平台上的双人弹射对战）：成熟之处在于同屏双人分区操作、回合交替与半场清空判胜的简洁规则，一局两三分钟。
- **我们要继承的成熟机制**：
  - 继承指弹棋的蓄力模型：按下拖拽决定方向与力度、松手发射，力度条可视化；
  - 继承棋子滑行物理：摩擦衰减、撞墙反弹、棋子间碰撞传递动量；
  - 继承半场清空判胜：规则一句话讲清，不需要计分表。
- **本作的独特魅力与微创新（Twist）**：
  - **中线小孔过线门**：不是把棋子弹进对方半场任意位置就算，而是必须穿过中线上的小孔才算过线——瞄准精度要求陡增，孔位固定可预判，弹射从「大力出奇迹」变成「瞄准+力度」双控制；
  - **借力撞击**：棋子穿孔后可继续撞击对方半场棋子，撞开对方挡路棋、或把自己留在对方半场的棋子二次撞动，一次弹射打出连锁；
  - **双模式同盘**：单人对 AI 与同屏双人共用同一盘面与规则，AI 难度三档，单人练手、双人热闹。
- **品类差异化定位（类型允许重复，杜绝一模一样）**：按查重底表（`GEM_INSTRUCTION-4.md` 第二节 100 款已上架清单，idiom 至 volley，储备清零）核对，与最接近的三款同属双人对战大类，但核心机制完全不同：
  - vs `tug`（指尖拔河）：`tug` 是狂点拼手速，核心是点击频率；本作核心是瞄准+力度控制的弹射过孔，没有狂点要素，节奏是回合制弹射；
  - vs `bumper`（微型回旋撞车）：`bumper` 是自旋冲撞的赛车碰撞，核心是驾驶与冲撞；本作无驾驶、无自旋，棋子只被弹射一次后靠物理滑行，目标是穿孔清空半场；
  - vs `airpuck`（双人霓虹气垫球）：`airpuck` 是气垫球对攻，核心是挡板实时拦截与击球进门；本作无挡板、无球门，是回合制弹射自己的棋子穿孔，操作模型与胜负判定都不同；
  - 只堵规则几乎一模一样的换皮，本作规则模型不同，可以立项。

## 3 · 玩法规则与交互说明

- **核心规则**：
  - 盘面构成：一块长方形桌面盘面，中线横贯盘面，中线上开 1–3 个小孔（孔位随难度/关卡变化）；盘面分上下（或左右）两个半场，每方初始棋子 5 枚，摆在本方半场底线附近；
  - 合法操作：轮到本方时，点选本方任意一枚棋子，向任意方向拖拽蓄力（拖拽距离决定力度、拖拽方向反向决定发射方向，带瞄准虚线与力度条），松手发射；棋子滑行、撞墙反弹、与他子碰撞，直至全部停稳，回合结束；
  - 穿孔判定：棋子完全穿过中线小孔进入对方半场即算「过线」，该子留在对方半场（对方半场因此多一子，成为对方要清走的负担）；未穿孔的棋子停在哪半场就留在哪半场；
  - 胜利条件：先把自己半场棋子全部清空（自己半场的棋子全部过线到对方半场）的一方获胜；
  - 失败条件：对方先清空自己半场，则本方落败；无平局，回合不限次，但单局设回合上限（建议 60 回合），上限到时以「自己半场剩余棋子少者」判胜，仍相同则判平局重开；
  - 容错与无死局说明：本作无随机生成关卡，盘面固定开局、物理全确定性，无死局；唯一可能僵局是双方棋子都堵在孔口互撞不进，回合上限+剩余棋子判胜机制兜底，保证每局必有结果。
- **操作与手感**：
  - 鼠标/触控：按下棋子拖拽蓄力、松手发射；拖拽时显示瞄准虚线（预瞄前段轨迹）与力度条，力度条满格后棋子轻微抖动提示已满力；
  - 键盘支持：方向键微调瞄准角度，空格按住蓄力、松开发射（力度随按住时长增长），Tab 切换选子；
  - **随时可暂停与失焦保护机制（实时物理必选）**：
    - *暂停/继续实体按钮*：顶栏常驻醒目的「暂停 / 继续」（Pause / Resume）按钮；
    - *暂停快捷键*：`P` 键、`Esc` 键即时切换暂停与继续（空格为蓄力键，不占用）；
    - *暂停视觉反馈*：暂停时盘面物理冻结、棋子定格，展示轻量半透明覆盖层（显示「已暂停 / PAUSED」，提供「继续」「重新开局」入口）；
    - *切后台自动暂停（Visibility Auto-Pause）*：切标签页、最小化窗口或失焦时自动静默暂停物理主循环，棋子冻结在原位，回来继续滑行，不会偷偷滑完；
  - 误触容错与操作缓冲：拖拽距离小于阈值松手视为取消蓄力不发射；棋子未停稳时禁止下一次操作（回合锁定），防连点误弹；蓄力中可拖回原点取消。
- **即开即玩与平滑选关设计（Instant Play，核心体验）**：
  - **首屏秒进对局**：初次打开直接呈现就绪盘面——默认单人对 AI（新手档）开局，棋子已摆好、轮到玩家弹射，无需前置点击即可上手；
  - **常驻显眼模式入口**：界面显眼处常驻醒目的「模式」按钮（单人对 AI 三档 / 同屏双人），点击以轻量抽屉或非阻塞弹层切换；结算面板提供「再来一局」与「模式」；
  - **严禁强制全屏遮罩阻塞首屏**：不可设计一进网页就弹全屏选模式大遮罩的反直觉流程。
- **模式与内容编排（严禁套路化，依游戏特质定制）**：
  - **严禁无脑套用“无尽冲分 + 每日挑战”**：本作不设无尽冲分、不设每日挑战，模式只服务于对战本身；
  - 模式一「单人对 AI」：三档难度——新手（瞄准偏差大、力度随机）、进阶（偏差小、会借力撞子）、大师（近乎精准、会规划撞击路线）；玩家可选先后手；
  - 模式二「同屏双人」：两人同屏轮流弹射，盘面上下半场各归一方，回合交替，适合当面热闹对局；
  - 盘面变体（轻量）：标准盘（中线 1 孔）、双孔盘（中线 2 孔）、三孔盘（中线 3 孔），孔越多越易过线、节奏越快，作为模式抽屉里的盘面选项，不做关卡制。
- **游戏目标与反馈体系**：
  - 核心目标指标：先清空自己半场获胜；局内反馈看「剩余棋子数」与「过线计数」，不看总分；
  - 胜利/阶段达成时的沉浸反馈仪式：最后一枚棋子穿孔过线时，中线小孔亮起光圈、棋子滑入对方半场定格，胜方半场清空，结算面板显示回合数、用时与「胜者」横幅，配指弹收尾音效。
- **双语核心词汇与数据键名规划（防英文界面夹杂中文）**：
  - 核心模式名中英对照：单人对 AI Solo vs AI / 同屏双人 Two Players (Same Screen)；
  - 难度名中英对照：新手 Novice / 进阶 Skilled / 大师 Master；
  - 核心实体中英对照：棋子 Puck / 中线小孔 Center Gate / 蓄力 Charge / 过线 Crossed / 半场 Half / 回合上限 Round Limit；
  - 数据层设计约束：所有模式、难度、盘面数据一律使用字符串 key 或 id（如 `mode_solo`、`ai_novice`、`board_1gate`），展示层通过 `i18n` 获取文本，严禁在数据文件中裸写中文。

## 4 · 题材原生视窗隐喻与音色质感（拒绝抄袭雷同）

- **题材风格关键词**：实木桌面、指尖弹射、铜孔门、棋子滑行、桌面竞技。
- **专属视窗物理隐喻（严禁连环参考老项目，拒绝左右双翼套路）**：
  - 物理承载形态：一块俯视的实木桌面——盘面就是整张木桌桌面，中线是桌缝，小孔是嵌在桌缝上的铜环孔门，棋子是木质圆片；整个游戏就是「在一张桌子上弹棋子过孔」，视窗即桌面本身；
  - **严禁直接照搬已有游戏结构**：绝对禁止不分题材一律机械切成“左翼卡片 + 中间视窗 + 右翼卡片”的三栏套路；本作是单块桌面一体盘面，计分与回合信息收进桌面顶部的窄条托盘，无左右双翼；
  - 严禁四角散落浮动按钮；严禁右侧机械堆叠白底/灰底 SaaS 表单卡片；
  - 保持全站一致的沉浸暗色底蕴与实体微质感：暗色背景衬木质桌面，木纹与棋子投影做足，不过分花里胡哨。
- **立体质感与渲染路线裁决**：
  - 裁决：Canvas 2D（95% 优先路线）。棋子滑行、碰撞、穿孔判定用 Canvas 2D 物理步进，木纹桌面与棋子投影用渐变与阴影实现拟真立体感；秒开、零加载、零发热；
  - 本作不尝试 Three.js：俯视桌面无需真三维空间交互，不触发三条红线（零外部 3D 模型、轻量材质低发热、UI 留 DOM 层）相关裁决；UI/HUD 全部在 DOM 层。
- **声效风格与材质音色规划（严禁千篇一律蜂鸣器）**：规划 6 种有材质感的声音，拒绝单音蜂鸣：
  1. **指尖弹射声**（松手发射）：指甲弹木片的脆响，短促噪声脉冲 + 木质共鸣；
  2. **棋子滑行摩擦声**（滑行中）：木片擦过桌面的沙沙声，音量随速度衰减；
  3. **棋子碰撞声**（子子相撞）：两块木片相撞的笃笃声，力度越大越响；
  4. **撞墙反弹声**（撞桌沿）：低频木质闷响；
  5. **穿孔过线声**（过线得分）：木片穿过铜环的清脆金属擦声 + 一记确认音；
  6. **胜负收尾声**（结算）：木片收拢的哗啦声 + 短促鼓点。
- **封面设计提案**：
  - 遵循 3D 软胶质感、单一居中主体（60-75% 无文字）、鲜艳渐变背景：一枚软胶质感的木质棋子正穿过铜环小孔，带运动拖影，背景为暖木色到深绿的渐变。

## 6 · 制作人拍板与开放探讨

列出 3 个关于玩法变体、关卡节奏或美术特色的好玩选项，供制作人（用户）快速拍板决断：

1. **孔位设计**：方案 A 固定中线单孔（推荐，瞄准精度要求最高、规则最纯粹）；方案 B 孔位每回合随机偏移（更刺激，但瞄准预判变难、新手挫败感上升）。
2. **过线棋子归属**：方案 A 过线棋子留在对方半场成为负担（推荐，清空判定最直观）；方案 B 过线棋子直接得分移除（节奏更快，但少了借力撞子的连锁乐趣）。
3. **AI 难度档位**：方案 A 三档（新手/进阶/大师，推荐，阶梯完整）；方案 B 两档（简单/困难，开发量小，但中间档玩家无处安放）。
