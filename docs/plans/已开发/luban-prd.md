## 1 · 创意概念与核心乐趣

- **游戏名称**：巧解鲁班锁 · 榫卯拆解 / Luban Lock · Mortise Puzzle / 建议 slug：`luban`（单个简短纯英文单词，符合 slug 极简契约；鲁班锁的英文通用名，无歧义）
- **一句话玩法**：转动 2.5D 等轴测的榫卯木锁，按唯一正确次序抽出木块，整锁拆散即胜。
- **核心乐趣与卖点**：
- 空间顿悟的快感：卡住时百思不得其解，一旦找对次序，木块一块接一块顺滑抽出，那种“原来如此”的瞬间是本作的全部；
- 机械结构的诚实手感：每块木头只能沿自己的长轴滑动，卡住就是卡住，绝不含糊，解开全凭空间想象不是碰运气；
- 文化亲近感：榫卯是刻在中国人手里的老手艺，玩的是游戏，摸到的是千年木作智慧；
- “咔哒”一声的仪式感：最后一块锁钥抽出的瞬间，整锁松散开来，成就感直接拉满。
- **核心循环**：观察锁体 ➔ 试探哪块能动 ➔ 按正确次序抽拉 ➔ 锁体渐渐松动 ➔ 全部拆散 ➔ 下一锁。

## 2 · 经典标杆与对标参考

- **成熟标杆原型**：
- **Interlocked（Armor Games，Flash 时代 2000 万玩家）**：3D 互锁木块拆解的品类标杆。最受认可的机制是“触摸拖动抽拉 + 依次解锁”——每块只能沿一个方向动，抽错顺序就卡死，抽对了整锁豁然开朗；以及“旋转视角找缝隙”的观察手感。
- **Burr Puzzle（Steam，鲁班锁 / Kongming Lock）**：把鲁班锁原样搬进电脑的官方作。最受认可的是“三档难度 + 20 余关”的编排与“最后插入的一根是锁钥”的结构逻辑——开锁容易装锁难，空间思维与耐心缺一不可。
- **六件套鲁班锁实物**：最经典的 6 根榫卯十字锁，六根带槽木条十字交错、最后一根锁死，是所有鲁班锁玩法的母本。
- **我们要继承的成熟机制**：
- 抽拉拆解的状态机：一次只动一块，动不了就提示被谁卡住；
- 锁钥结构：每具锁有一根“钥匙块”，抽掉它整锁松动；
- 旋转视角观察：等轴测四向切换，找缝隙、看卡位。
- **本作的独特魅力与微创新（Twist）**：
- 平台完全空白的赛道：站内尚无榫卯 / 机械拆解类，2.5D 等轴测 + 榫卯是独一份；
- “自由块高亮”提示系统：轻点任意木块，立刻知道它能不能动、被哪块卡住，把实物锁“摸不着头脑”的挫败感变成可学习的推理；
- 每关一句榫卯小知识：过关后弹一句（如“鲁班锁又名孔明锁，相传为三国孔明所创”），寓教于乐，差异化拉满；
- 拆散后可“一键复原”重玩：拆完的锁能拼回去反复练，适合收藏与分享。
- **品类差异化定位（类型允许重复，杜绝一模一样）**：与站内解谜类同属大类，但规则模型截然不同——本作是“空间次序拆解”，不是推盘、不是连线、不是消除；胜负不靠手速与连击，靠找对唯一正确次序，坚决杜绝换皮。

## 3 · 玩法规则与交互说明

- **核心规则**：
- **盘面构成**：一具 2.5D 等轴测榫卯木锁居中（4~12 根木块，按关卡递增），木块带榫槽、相互咬合；侧边显示已抽出块数与剩余块数。
- **玩家合法操作**：拖动任意木块沿其长轴抽拉（鼠标拖拽或触屏滑动）；点按木块选中，查看它是否可动；滚轮或双指缩放锁体；R 键切换等轴测视角（四向）。
- **胜利条件与失败条件**：按唯一正确次序把全部木块抽出即过关；本作无失败判定——抽错方向时木块只会轻晃提示被卡住，不扣分、不重开，随时可以悔棋重来。
- **容错与无死局说明**：每关由解法倒推生成——先定一条拆解次序，再按次序拼装成锁，保证唯一正确次序一定存在；另设三档提示（轻提示：高亮下一块可动块；中提示：显示次序箭头；重提示：直接演示一步抽法）与不限次悔棋。
- **数值（初版建议，开发时可微调）**：36 关，木块数 4~12 根；评级按提示用量与抽拉总步数（金榫 = 零提示、步数 ≤ 解法步数 ×1.2；银榫 = 轻提示 ≤2；铜榫 = 其余）。
- **操作与手感**：
- 鼠标拖动抽拉木块，触屏同理；点按木块查看可动性（可动泛绿光、被卡泛红光并标出卡住它的那块）；R 键旋转视角，U 键悔棋，H 键提示；
- 抽拉有木质摩擦的阻尼感动画，抽出瞬间“咔哒”一声 + 木块飞入侧边托盘；卡住时木块轻晃两下 + 闷响，反馈必须一眼看懂；
- 误触容错：拖错方向不惩罚，松手即回弹；悔棋不限次，可一路退回开局。
- **随时可暂停与失焦保护机制**：本作是纯静态解谜，无倒计时压力，不强制常驻暂停键；带用时计时器的模式在菜单呼出时冻结计时；切标签页不影响局势（静态盘面天然静止）。
- **即开即玩与平滑选关设计**：初次打开直接进入第 1 关（六件套十字锁），锁体直接就绪，无需前置点击；顶栏常驻醒目的「选关」按钮，点击以轻量抽屉展示章节关卡网格；结算面板提供「下一关」与「选关」。
- **模式与内容编排（依玩法特质定制，不套无尽冲分）**：
- **章节关卡制（默认）**：36 关，6 章，每章一种锁型——十字锁、六合锁、八卦锁、孔明锁、鲁班球、机关盒；每章引入一种新结构（新槽型 / 新卡位方式）；
- **金银铜榫评级**：每关按提示用量与步数评级，集满一章金榫解锁该章榫卯小知识合集；
- **自由拼锁（进阶）**：通关全部 36 关后解锁——给一堆散块，玩家自己按榫卯规则拼回完整锁体（反向玩法，拼对即胜）。
- **游戏目标与反馈体系**：核心指标不是总分，而是**提示用量**与**榫位评级**；过关结算展示“拆解回放”（按正确次序逐块抽出的缩时动画），金榫时锁钥块镀金高亮。
- **双语核心词汇与数据键名规划**：
- 模式：章节关卡 Level Mode / 自由拼锁 Free Build / 提示 Hint / 悔棋 Undo；
- 实体：木块 Block / 锁钥 Key Block / 榫 Tenon / 卯 Mortise / 十字锁 Cross Lock / 孔明锁 Kongming Lock；
- 数据层约束：所有关卡、锁型、难度数据一律用字符串 key 或 id（如 `level_07`、`lock_cross_6`），展示层通过 `i18n` 获取文本，严禁在数据文件里裸写中文。

## 4 · 题材原生视窗隐喻与音色质感（拒绝抄袭雷同）

- **题材风格关键词**：榫卯、老木匠、案头、等轴测、温润。
- **专属视窗物理隐喻**：**“木匠案头的一把老锁”**——整个界面就是一张刨花木工作台：锁体摆在台中央，旁边散放着木屑与一把小木锤（装饰），已抽出的木块整齐码在台边的木托盘里。拒绝左右双翼三栏套路，锁体居中、信息围着锁体走。
- **立体质感与渲染路线裁决**：纯 DOM + CSS 3D 为主（木块用 CSS 3D 长方体拼出等轴测造型，固定四向视角切换；木纹用 CSS 渐变模拟），Canvas 2D 只做木屑飘落粒子。**不采用 Three.js**——视角固定为等轴测四向切换，无真三维自由翻转需求，CSS 3D 已足够且秒开零发热。
- **声效风格与材质音色规划（4~6 种，拒绝单音蜂鸣器）**：
- 木块抽拉：木质摩擦的沙沙声（物理噪声滤波）；
- 卡住闷响：低频木头闷哼（失谐多振荡器轻敲）；
- 抽出“咔哒”：清脆榫卯落位声（FM 合成）；
- 锁体松动：连串轻响（多块依次松动的叠奏）；
- 过关：小木槌轻敲两下 + 编钟；
- 复原拼合：木块归位的连贯“咔哒”声。
- **封面设计提案**：3D 软胶质感、单一居中主体（一把榫卯十字锁，占 60~75%，无文字）、鲜艳渐变背景（暖木黄到深褐的案头光影）。

## 6 · 制作人拍板与开放探讨

1. **视角：固定等轴测四向切换 vs 自由旋转**——方案 A：固定四向切换（CSS 3D 够用，秒开零发热）；方案 B：自由旋转（需 Three.js，违背 95% 路线且开发成本翻倍）。推荐 A。
2. **提示：三档提示 vs 只给“哪块能动”**——方案 A：三档提示（轻/中/重，新手友好，卡关不劝退）；方案 B：仅高亮可动块（硬核，但新手容易卡死弃坑）。推荐 A。
3. **文化味：每关一句榫卯小知识 vs 纯解谜**——方案 A：带小知识（差异化，寓教于乐，过关有额外收获）；方案 B：纯解谜（更干净）。推荐 A。
