## 1 · 创意概念与核心乐趣

- **游戏名称**：甲骨文溯源连线 / Oracle Bone Tracing · Oracle Glyph Match / slug：`oracle`（单个简短纯英文单词）
- **一句话玩法**：看甲骨象形猜本字，连线配对即通关。（16 字）
- **核心乐趣与卖点**：
  - **认字即通关的顿悟快感**：玩家盯着一片三千年前的甲骨刻痕，看它长得像什么——像一只鸟、一条鱼、一轮太阳——猜出它就是今天的「鸟」「鱼」「日」。猜中那一下，字形从甲骨到楷书的演变动画当场放给你看，是全站唯一「玩着玩着就认识了汉字祖宗」的文化认字解谜。
  - **不是背字，是看图猜字**：甲骨文天生是象形画，玩家不需要任何文字学基础，靠眼睛就能猜，猜错也有演变提示兜底，零挫败、纯发现。
  - **连线配对的确定性**：每关一组甲骨字形与一组本字（或释义），连对一对点亮一对，连线反馈干脆利落，像把散落的甲骨片一片片对上号。
- **核心循环**：看甲骨字形 ➔ 猜本字并连线配对 ➔ 正确即播放字形演变动画并点亮 ➔ 整关配齐通关 ➔ 解锁下一组字族（动物、自然、人体、器物）。

## 2 · 经典标杆与对标参考

- **成熟标杆原型**：
  - **甲骨文认字/汉字演变类文化产品**（博物馆互动屏、《汉字》类科普应用、甲骨文表情包）：核心资产是「甲骨字形 → 本字」的象形对应关系与字形演变展示，成熟之处在于选字皆为象形性强、演变链完整的字，且每个字都有可视化演变过程。
  - **连连看式配对**（本站 `link-up` 喜福连连看、`pair-link` 琉璃灯市·连连看即属此类）：核心手感是点选两个相同元素、连线消去，反馈即时、节奏轻快；成熟之处在于「找相同」的低门槛与连线成功时的爽感。
- **我们要继承的成熟机制**：
  - 借甲骨文产品的选字标准：只选象形性强、演变链可考、人工校验过的字，拒绝冷僻字与争议字；
  - 借连连看的点选—连线—消去反馈节奏，但把「找相同图案」换成「认甲骨猜本字」，从比对速度变成认知推理；
  - 借字形演变动画作为配对成功奖励：甲骨 → 金文 → 小篆 → 楷书的笔画演变，让每次配对都是一次微型文化奖励。
- **本作的独特魅力与微创新（Twist）**：
  - **认字即通关**：配对依据不是图案相同，而是「这片甲骨画的是什么」，玩家靠象形推理而非记忆比对；
  - **演变动画作奖励**：配对成功不只是消去，而是点亮并播放该字三千年的字形演变，把科普知识做成通关奖励本身；
  - **字族章节化**：按动物、自然、人体、器物等字族编排关卡，玩家一关认一族字，通关即攒齐一族「汉字祖宗」。
- **品类差异化定位（类型允许重复，杜绝一模一样）**：按查重底表（`GEM_INSTRUCTION-4.md` 第二节 100 款已上架清单，idiom 至 volley，储备清零）核对，全站无同类文化认字解谜，与最接近的三款机制差异如下：
  - vs `hanzi`（字灵拆拆乐）：`hanzi` 是拆字重组触发物理的构字玩法，核心动作是把汉字拆成部件再拼；本作核心动作是认甲骨象形猜本字并连线溯源，不拆字、不拼字、无物理触发，规则模型完全不同；
  - vs `idiom`（成语纵横榜 · 典故图鉴）：`idiom` 是纵横填字榜，核心是成语知识与填格推理；本作是字形—本字连线配对，靠象形观察而非成语知识，无填字格；
  - vs `wordle`（每日猜词）：`wordle` 是每日猜英文单词、靠字母颜色反馈收窄范围；本作是每关一组甲骨—本字配对、靠象形推理一次命中，无每日限制、无字母反馈；
  - 与 `link-up`/`pair-link`（连连看）同属配对大类，但那两款比对的是相同图案且连线须走通路消去；本作比对的是甲骨字形与本字的对应关系、无通路规则、无消去，只是点亮。只堵规则几乎一模一样的换皮，本作规则不同，可以立项。

## 3 · 玩法规则与交互说明

- **核心规则**：
  - 盘面构成：每关一幅「甲骨拓片盘面」，左侧（或上方）是一组甲骨字形卡（4–8 张，刻痕质感），右侧（或下方）是一组本字卡（现代汉字 + 释义小字），两组数量相等、顺序打乱；
  - 合法操作：点选一张甲骨卡，再点选一张本字卡（或拖拽连线），系统判定是否对应；正确则两卡之间拉出溯源线、播放字形演变动画并点亮锁定；错误则轻微抖动提示、不扣血不惩罚，可继续尝试；
  - 胜利条件：整关全部甲骨—本字配对点亮即通关；
  - 失败条件：无失败。纯逻辑认字玩法，不设倒计时、不设错误上限，玩家可无限次尝试；用时与错误次数只用于星级评级（三星：零错误；二星：错误 ≤2 次；一星：通关即得）；
  - 容错与无死局说明（题库人工校验 + 唯一可解配对保证）：题库全部人工校验，只收录象形性强、演变链可考的甲骨字，争议字与冷僻字一律剔除；每关生成时执行唯一性检查——同一关内不得出现两个甲骨字形对应同一本字、也不得出现同一甲骨字形可对应两个本字（如「日」「目」同关须确保字形可辨且释义不混淆），保证每关有且仅有一套正确配对，100% 可解；本字卡打乱顺序只打乱位置、不打乱对应关系，不存在随机死局。
- **操作与手感**：
  - 鼠标/触控：点选甲骨卡 → 点选本字卡；或从甲骨卡拖拽至本字卡连线，松手判定。触控点按区域不小于卡片本身，防误触；
  - 键盘支持：方向键/Tab 在卡片间移动焦点，Enter 确认点选，Esc 取消当前点选；R 键重开本关；
  - 随时可暂停与失焦保护：本作是无时间压力的纯静态回合制认字解谜，天然静止，无需强制常驻暂停按钮；但含用时计时（用于星级评级），呼出菜单/选关时必须冻结计时，切标签页（visibilitychange）时自动冻结计时，回来继续，不清零已配对进度；
  - 误触容错与操作缓冲：点选后 300ms 内可点同一卡取消；连线判定有 120ms 输入缓冲，连点不会连错两对。
- **即开即玩与平滑选关设计（Instant Play，核心体验）**：
  - **首屏秒进对局**：初次打开直接呈现第 1 关（或记忆存档关卡）的可操作就绪盘面，甲骨卡与本字卡直接就绪，无需前置点击即可认字连线；
  - **常驻显眼选关入口**：在界面显眼处（顶栏或控制托盘）常驻醒目的「选关」按钮，点击时以轻量抽屉或非阻塞弹层展示字族章节网格；通关结算面板提供「下一关」与「选关」；
  - **严禁强制全屏遮罩阻塞首屏**：不可设计一进网页就弹全屏大选关卡片的反直觉流程。
- **模式与内容编排（严禁套路化，依游戏特质定制）**：
  - **严禁无脑套用“无尽冲分 + 每日挑战”**：本作采用精心编排的字族章节关卡制，不设无尽冲分、不设每日挑战；
  - 章节规划（建议 4 章 × 6 关 = 24 关）：第 1 章「山川日月」（日、月、山、水、雨、云等自然字）、第 2 章「鸟兽虫鱼」（鸟、鱼、马、牛、羊、犬等动物字）、第 3 章「人身百态」（人、目、手、足、口、耳等人体字）、第 4 章「器物农耕」（车、门、刀、田、禾、舟等器物字）；每章引入更抽象的字形（从纯象形到象形+指事），三星/用时评级；
  - 每关字数递进：第 1 章每关 4 对，后续章节逐步增至 6–8 对，字形辨识难度同步上升。
- **游戏目标与反馈体系**：
  - 核心目标指标：通关进度（已认字数/总字数）、每关三星评级、字族收集进度（已攒齐的字族徽章），不看总分；
  - 胜利/阶段达成时的沉浸反馈仪式：整关配齐时，全部甲骨卡依次播放字形演变动画并汇成一幅完整的甲骨拓片卷轴，卷轴缓缓展开，配编钟音效，结算面板显示用时、错误次数与星级。
- **双语核心词汇与数据键名规划（防英文界面夹杂中文）**：
  - 核心模式名中英对照：章节闯关 Chapter Mode / 字族图鉴 Glyph Atlas；
  - 章节名中英对照：第 1 章·山川日月 Chapter 1: Sun & Moon / 第 2 章·鸟兽虫鱼 Chapter 2: Birds & Beasts / 第 3 章·人身百态 Chapter 3: The Human Form / 第 4 章·器物农耕 Chapter 4: Tools & Fields；
  - 核心实体中英对照：甲骨字形 Oracle Glyph / 本字 Modern Character / 释义 Meaning / 溯源线 Tracing Line；
  - 英文模式特别约束：甲骨字形本身是图形（SVG/字形图），不随语言切换改变；本字卡在英文模式下保留汉字字形（作为被认对象本身），释义改为英文（如「日」释义 Sun），界面其余文案 100% 英文、零汉字界面文本。汉字仅作为游戏数据对象出现，不作为界面文案；
  - 数据层设计约束：所有字条、章节数据一律使用字符串 key 或 id（如 `glyph_ri`、`chapter_nature`），展示层通过 `i18n` 获取文本，严禁在数据文件中裸写中文界面文案。

## 4 · 题材原生视窗隐喻与音色质感（拒绝抄袭雷同）

- **题材风格关键词**：甲骨拓片、殷墟刻痕、朱砂拓印、宣纸卷轴、编钟余音。
- **专属视窗物理隐喻（严禁连环参考老项目，拒绝左右双翼套路）**：
  - 物理承载形态：一幅横向展开的甲骨拓片卷轴——盘面是整块做旧宣纸拓片，甲骨字形卡像刻在骨片上的刻痕浮雕，溯源线是朱砂红的拓印笔触；卷轴两端有木轴，通关时卷轴展开仪式与视窗隐喻一体；
  - **严禁直接照搬已有游戏结构**：绝对禁止不分题材一律机械切成“左翼卡片 + 中间视窗 + 右翼卡片”的三栏套路；本作是单幅卷轴一体盘面，甲骨卡与本字卡同在拓片上分区排布，无左右双翼；
  - 严禁四角散落浮动按钮；严禁右侧机械堆叠白底/灰底 SaaS 表单卡片；选关入口与计时收进卷轴顶部的窄条托盘；
  - 保持全站一致的沉浸暗色底蕴与实体微质感：暗色背景衬宣纸拓片，刻痕有凹凸阴影，不过分花里胡哨。
- **立体质感与渲染路线裁决**：
  - 裁决：纯 DOM + CSS 3D（95% 优先路线）。甲骨字形用 SVG 字形图，刻痕凹凸用 CSS 阴影与渐变实现，演变动画用 SVG 路径描边动画，溯源线用 Canvas 2D 或 SVG 绘制；秒开、零加载、零发热；
  - 本作不尝试 Three.js：无真三维空间交互需求，不触发三条红线（零外部 3D 模型、轻量材质低发热、UI 留 DOM 层）相关裁决。
- **声效风格与材质音色规划（严禁千篇一律蜂鸣器）**：规划 5 种有材质感的声音，拒绝单音蜂鸣：
  1. **刻刀凿骨声**（点选甲骨卡）：短促的骨质敲击噪声 + 高频刻痕摩擦，物理噪声滤波合成；
  2. **朱砂拓印声**（连线成功）：宣纸摩擦的沙沙声叠一记低频闷响，像拓包压过纸面；
  3. **编钟单音**（字形演变动画）：FM 合成的青铜编钟音，带长混响尾巴；
  4. **错配轻叩声**（连错）：木鱼式低闷轻叩，提示而非惩罚；
  5. **卷轴展开声**（通关仪式）：宣纸展开的沙沙声 + 编钟琶音收尾。
- **封面设计提案**：
  - 遵循 3D 软胶质感、单一居中主体（60-75% 无文字）、鲜艳渐变背景：一片软胶质感的甲骨片居中，骨片上刻着「日」字甲骨字形并连着朱砂溯源线，背景为朱砂红到墨色的渐变。

## 6 · 制作人拍板与开放探讨
