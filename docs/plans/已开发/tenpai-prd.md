## 1 · 创意概念与核心乐趣

- **游戏名称**：雀神听牌王 · 听牌速判 / Tenpai King · Wait Finder / 建议 slug：`tenpai`（单个简短纯英文单词，符合 slug 极简契约；即日麻“听牌”术语，无歧义）
- **一句话玩法**：面对一手复杂麻将牌，限时揪出全部可胡听牌，并算出最高番数。
- **核心乐趣与卖点**：
- 眼力与算力的双重快感：一眼看穿听牌的“雀神”感，别人还在数搭子，你已经点完了全部听牌；
- 限时压迫下的心跳：30 秒倒计时滴答作响，找得越快分越高，找漏一张就扣分，紧张感拉满；
- 番数翻倍的贪心抉择：同一手牌不同听牌番数不同，选番最高的路线才得满分——不只要找全，还要找“值钱”的；
- 从新手到雀神的成长线：从两面听一路练到七对、国士等特殊形，练完真能上桌炫技。
- **核心循环**：看牌 ➔ 拆搭子找听牌 ➔ 点出全部可胡牌 ➔ 选最高番路线 ➔ 结算讲解 ➔ 下一手。

## 2 · 经典标杆与对标参考

- **成熟标杆原型**：
- **TileSense Riichi Dojo（Wait Finder）**：听牌训练的现代标杆。最受认可的机制是“点出全部听牌 + 计时计分 + 揭示完整听牌表与形状讲解”——答完不只告诉你对错，还把每张听牌的胡牌形状讲明白，练一次长一次功力。
- **Riichi Calc（日麻计算器）**：算听牌与番符的工具标杆。最受认可的是“任意 14 张牌算出全部胡牌组合 + 番符” 的求解器思路，本作的题库生成与答案校验直接沿用这套枚举逻辑。
- **Mahjong Lab 向听训练（15 秒计时）**：计时答题的标杆。最受认可的是“15 秒限时 + 答对按剩余时间加分 + 错一题即结算”的压迫式计分，紧张感与公平性兼备。
- **我们要继承的成熟机制**：
- 听牌查找 + 计时计分 + 完整答案揭示与讲解（状态机清晰，对错一目了然）；
- 求解器枚举答案（题库与答案都由程序算出，不靠人工出题）；
- 限时加分（答得越快分越高）。
- **本作的独特魅力与微创新（Twist）**：
- 平台完全空白的赛道：站内尚无麻将 / 听牌训练类，听牌速判是麻将圈公认的“基本功”，受众明确；
- 不只找听牌，还要“算最高番”：同一手牌不同听牌番数不同，选番最高的路线才得满分——把“找全”升级成“找全 + 找值钱”，贪心抉择是本作独有的第二层博弈；
- 中文规则为主 + 日麻模式可选：国标常用番种为主，另设日麻模式（立直、番符），两种规则各有独立题库；
- “雀神榜”评级制：按准确率与速度评段位（雀士 / 雀杰 / 雀豪 / 雀神），练完有段位可晒。
- **品类差异化定位（类型允许重复，杜绝一模一样）**：与站内棋牌 / 益智类同属大类，但规则模型截然不同——本作是“限时听牌速判 + 番数抉择”，不是打麻将对局、不是麻将接龙；胜负不靠摸牌运气，靠眼力、算力与速度，坚决杜绝换皮。

## 3 · 玩法规则与交互说明

- **核心规则**：
- **盘面构成**：一手 13 张麻将牌一字排开（已听牌，1 向听内），下方是 34 种牌的点选区，顶栏是 30 秒倒计时与当前连对数。
- **玩家合法操作**：点选点选区里的牌，标记为“可胡听牌”（可多选）；选完后按“提交”交卷；提交后系统自动取其中番数最高的一张计分（玩家也可手动指定一张为“主攻听牌”，指定对了有额外加分）。
- **胜利条件与失败条件**：每题答完即结算——找全全部听牌且主攻听牌番数最高得满分；漏点一张扣 20%，错点一张扣 30%，超时未提交按已选牌计分；连续答对有连对加成（每连 +5%）。
- **容错与无死局说明**：题库由求解器生成——每手牌经完整枚举验证听牌表非空且番数可算，绝不会出现“无听牌”或“算不出番”的死题；答错后揭示完整听牌表、每张牌的番数与胡牌形状讲解，可反复看懂再下一题。
- **数值（初版建议，开发时可微调）**：每题 30 秒（大师章 20 秒）；满分 100（找全 60 + 主攻番最高 40）；番数按简化番表计算（平胡、碰碰胡、清一色、七对、混一色等 12 个常用番种，开发时以策划附表为准）；60 题分 3 章。
- **操作与手感**：
- 鼠标点牌选择，触屏同理；键盘 1~9 快速选牌，Enter 提交；P / Esc 暂停（计时冻结）；
- 点牌有脆响 + 牌面弹起动画，提交后逐张揭示对错（对的泛绿光、漏的补亮、错的泛红光），番数最高的牌镀金高亮；
- 误触容错：提交前可随时取消已选牌；倒计时剩 5 秒时滴答声加快提醒。
- **随时可暂停与失焦保护机制**：本作含限时答题，必须配备顶栏常驻醒目的「暂停 / 继续」按钮与 P / Esc / 空格快捷键，暂停时冻结倒计时并显示轻量半透明遮罩（继续 / 重新开始）；切标签页或最小化时自动静默暂停，回来后局势与剩余时间原样不动。
- **即开即玩与平滑选关设计**：初次打开直接进入第 1 题，牌面与倒计时直接就绪，无需前置点击；顶栏常驻醒目的「选关」按钮，点击以轻量抽屉展示章节题库网格；结算面板提供「下一题」与「选关」。
- **模式与内容编排（依玩法特质定制，不套无尽冲分）**：
- **闯关制（默认）**：60 题，3 章——基础听牌（两面听、三面听）、多面听（四面以上，含嵌张边张）、特殊形（七对、国士、十三幺等）；每章 20 题，按准确率评段位；
- **计时挑战**：60 秒连答，答对加 5 秒（上限 60 秒），错一题即结算，成绩只作本局记录；
- **每日一练**：每天 5 题固定题库（全站同题），答完可看当日平均分，纯练手不设排行；
- **日麻模式**：切换后题库与番表换成日麻规则（立直、番符、宝牌），与中文模式独立计分。
- **游戏目标与反馈体系**：核心指标不是总分，而是**准确率**与**段位**（雀士 / 雀杰 / 雀豪 / 雀神四档，按章节准确率晋升）；答完一题即时讲解胡牌形状，错题自动收入“错题本”可重练。
- **双语核心词汇与数据键名规划**：
- 模式：闯关制 Level Mode / 计时挑战 Time Attack / 每日一练 Daily Drill / 日麻模式 Riichi Mode；
- 实体：听牌 Tenpai / 番数 Fan / 胡牌 Winning Tile / 搭子 Meld / 雀神段位 Dan Rank；
- 数据层约束：所有题库、番表、段位数据一律用字符串 key 或 id（如 `q_001`、`fan_qingyise`、`dan_master`），展示层通过 `i18n` 获取文本，严禁在数据文件里裸写中文；中日两种规则各建独立数据文件，不混表。

## 4 · 题材原生视窗隐喻与音色质感（拒绝抄袭雷同）

- **题材风格关键词**：绿呢麻将桌、听牌、番数、雀神、限时心跳。
- **专属视窗物理隐喻**：**“一张绿呢麻将桌”**——整个界面就是一张麻将桌：手牌一字排开，牌墙在桌边码着，番数牌像筹码一样摞在桌角，倒计时是一盏沙漏。拒绝左右双翼三栏套路，牌桌居中、信息压在上下两条。
- **立体质感与渲染路线裁决**：纯 DOM 为主（麻将牌面天然适合 DOM + CSS 3D 薄片，牌面花色用 CSS 绘制），Canvas 2D 只做胡牌礼花粒子。**不采用 Three.js**——牌面是平面点选交互，无真三维空间翻转需求，DOM 已足够且秒开零发热。
- **声效风格与材质音色规划（4~6 种，拒绝单音蜂鸣器）**：
- 摸牌：沙沙声（物理噪声滤波）；
- 点牌：脆响（失谐多振荡器轻敲）；
- 计时滴答：木鱼轻敲（随剩余时间加快）；
- 答对：编钟一声（FM 合成）；
- 胡牌：锣鼓三声（打击乐采样感合成）。
- **封面设计提案**：3D 软胶质感、单一居中主体（一手麻将牌 + 一张“胡”字牌，占 60~75%，无文字）、鲜艳渐变背景（绿呢桌绿到金黄）。

## 6 · 制作人拍板与开放探讨

1. **规则：国标常用番种为主 vs 日麻立直为主**——方案 A：国标为主 + 日麻模式可选（受众最广，两种玩家都照顾到）；方案 B：只做日麻（更垂直，但丢了中文麻将玩家）。推荐 A。
2. **限时：每题 30 秒 vs 整局总计时**——方案 A：每题 30 秒（节奏紧凑，每题都是冲刺）；方案 B：整局 5 分钟（可自行分配时间，策略味浓）。推荐 A。
3. **难度：固定题库 60 题 vs 随机出题**——方案 A：固定题库 + 每日一练（可复盘、可比拼、错题可重练）；方案 B：全随机（练不完，但无法复盘）。推荐 A。
