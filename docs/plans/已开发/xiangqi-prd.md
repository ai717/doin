## 1 · 创意概念与核心乐趣

- **游戏名称**：象棋残局 / Xiangqi（副标：木桌对弈 · 残局解题）/ 建议 slug：`xiangqi`
- **一句话玩法**：红木棋桌上与阶梯 AI 对弈，或破解定式残局——在限定步数内以红方杀棋取胜。
- **核心乐趣与卖点**：
  - **千年国粹的经典深度（Millennial Chess Depth）**：车马炮兵士相将，32 子百般杀法——象棋是"最大经典空白"补位，规则成熟、人人识棋、深度无限；
  - **残局解题的顿悟快感（Endgame Insight · 用户点名）**：给定棋谱残局，N 步内红先杀——一着"马后炮"、一记"双车错"，解出瞬间的顿悟是解谜类游戏最顶级的爽感；**求解器校验每关可解**，绝无死局与无解残局；
  - **阶梯 AI 的成长曲线（Tiered AI Ladder · 用户点名）**：新手（深度 1 + 30% 失误）到大师（深度 3 + 零失误）五档，每一步晋升都是可见的实力跃迁——失误率分档由确定性种子注入，公平可测；
  - **木桌对弈的沉浸质感（Wooden Table Duel）**：红木棋桌、浮雕棋子、落子"笃"声、茶室暖光——千年棋文化的仪式感，题材零风险、全站无同款视窗；
  - **品类空白补位（Board-Game Gap · 用户点名）**：全站棋类对弈仅五子棋（`gomoku`）、黑白棋（`reversi`）两款，象棋是最大经典空白。
- **核心循环**：
  ```
  开局/载入残局 ➔ 走子（拖放或点选）➔ 规则引擎校验（合法走法/应将强制）
       ↑                                                    ↓
  吃子/将军（音效反馈）← 阶梯 AI 应着（minimax+失误率）← 局面更新
       ↓（残局模式：步数 ≤ par）                    ↓（对战模式：终局）
  杀棋/困毙/和棋 ➔ 星级 / 胜负记录 ➔ 下一关 / 更高 AI 档
  ```

**我们要继承的成熟机制**：
1. **完整象棋规则引擎（Full Rule Engine）**：走法生成（车马炮兵士相将各自走法）、蹩马腿/塞象眼/九宫限制/将帅照面、将军应将强制、杀棋/困毙/和棋终局——千年规则一字不省；
2. **阶梯 AI 分档（Tiered AI）**：minimax 深度 1→3 + 失误率 30%→0% 五档，失误走子由确定性种子注入——继承"失误率分档"的成熟对弈 AI 范式（平台 `reversi`、`gomoku` 已验证）；
3. **残局闯关编排（Endgame Campaign）**：定式残局 + 限定步数杀棋目标 + 三星评级——继承平台"章节目标 + 求解器可解性校验"范式；
4. **循环局面确定性处理（Repetition Handling）**：三次重复局面判和 + 长将长捉犯规判负——确定性、可测、杜绝无限循环；
5. **确定性契约（Deterministic Contract）**：120Hz 纯函数帧步进、种子注入、同种子重放一致、棋子数守恒（本策划案的核心契约）。

**本作的差异化微创新（拒绝无聊照搬）**：
1. **残局求解器全量校验（Solver-Verified Endgames · 用户点名）**：每关残局由求解器断言"存在唯一杀法路径、mate-in-N 可达、平凡一步杀过滤"——复用平台 `reversi/tools/gen-puzzles.mjs` 验证体系，**残局零无解、零死局、可背谱**；
2. **杀法类型章节制（Mate-Type Chapters）**：残局按杀法类型编章（双车错→马后炮→车马冷着→经典名局），每章教一种杀法再考一组残局——"学杀法 → 用杀法"的成长闭环；
3. **阶梯 AI 实力徽章（Tier Badges）**：击败各档 AI 获得木刻实力徽章（新手木牌→大师金木牌），对战记录写进纸质记分簿——晋升感可视化；
4. **红木棋桌原生视窗（Redwood Chess Table）**：对弈是红木棋桌上的一局——浮雕棋子、纸质记分簿、木制棋盒、泛黄棋谱卡全原生，全站无同款视窗；
5. **即开即玩零门槛（Instant Play）**：首屏直接载入可玩盘面（默认残局第 1 关），无前置遮罩，选关/模式入口常驻——平台最新契约。

## 3 · 玩法规则与交互说明

### 3.1 场景构成（红木棋桌，俯视 2D）
- **棋盘**：标准 9 列 × 10 行（90 个交叉点），含河界（楚河汉界）与双方九宫（3×3 斜线宫）；
- **棋子**：32 子——红方（帅/仕/相/马/车/炮/兵：1+2+2+2+2+2+5）与黑方（将/士/象/马/车/炮/卒同数），木质浮雕圆棋（红木色与乌木色）；
- **纸质记分簿（Scorebook）**：桌边纸质记分簿记录对战胜负、连胜、残局星级；
- **木制棋盒（Chess Box）**：收纳棋子与操作（重摆/悔棋/选关）；
- **泛黄棋谱卡（Endgame Card）**：残局模式显示棋谱卡——杀法提示（可开关）、限定步数（par）、目标说明。

### 3.2 判定与规则（核心契约：完整规则引擎）
1. **走法合法性**：所有走法经规则引擎校验——车直线、马走日（蹩马腿禁）、炮翻山打子/直行、士相九宫内/田字（塞象眼禁）、兵卒过河前后左右（未过河仅前）、将帅九宫内直行一格 + **将帅照面禁对**；
2. **将军与应将（Check & Block）**：将军后对手必须应将（垫子/走将/吃将），无法应将即**杀棋（Checkmate）**；无子可动且未被将军即**困毙**（按规则判负）；
3. **循环局面（Repetition）**：同一局面第 3 次出现判和；长将（连续将军对方必须应将且已超 3 次）犯规判负——确定性处理，可测；
4. **吃子判定（Capture）**：走子落点有对方棋子即可吃（炮需隔一子）；吃子后该子移出棋盘；
5. **终局判定**：杀棋 / 困毙 = 负方输；和棋（三次重复 / 双方无取胜子力残局）判和；
6. **残局模式判定**：红先走，**限定步数 par 内完成杀棋**即过关（黑方所有应着由引擎模拟最佳防守）；超步数或红方被将死/和棋 = 本关失败可重试。

### 3.3 模式与内容编排（拒绝套路化三件套）
- **残局闯关（Endgame Campaign，主打）**：**4 章 × 6 关 = 24 关**，评价体系 = 星级 + 用步数（≤ par / 零失误 / 杀法正确），绝不做无尽冲分：
  - 第 1 章·双车错：基础双车/双炮杀法残局，学直线重子协同；
  - 第 2 章·马后炮：马炮组合杀法残局，学马炮冷着；
  - 第 3 章·车马冷着：车马残棋杀法，学深层次配合；
  - 第 4 章·经典名局：传统名局残局（求解器校验可背谱），收官演出；
- **阶梯 AI 对战（Duel vs AI）**：红方执先对弈，**五档 AI**（新手 depth1+30% 失误 / 入门 depth1+10% / 进阶 depth2+5% / 高手 depth3 / 大师 depth3+零失误），击败各档获木刻实力徽章；记录胜负/连胜于纸质记分簿；
- **同屏双人对弈（2P Local）**：同一红木棋桌轮流走子，完整规则（见拍板项 3）。

### 3.4 无死局与公平保证（数学可解性）
1. **残局可解性全量校验（用户点名）**：每关残局由求解器（`tools/gen-puzzles.mjs` 复用范式，negamax + 杀棋检测）断言：
   - **存在唯一杀法路径**（红方至少一条必杀线）；
   - **mate-in-N 可达**（par 步内可杀，黑方最佳防守下亦可）；
   - **平凡一步杀过滤**（非一步杀关，首着不得是直接将军即杀）；
   - 求解器结果写入测试断言，**每次重跑复核**——残局零无解、零死局；
2. **AI 公平性**：五档失误率固定、失误走子由确定性种子注入（同种子可重放），大师档零失误但深度受限（depth3），人类始终存在合理胜机——不设计不可战胜的完美 AI；
3. **规则确定性**：走法合法性、应将强制、循环局面、终局判定全部纯函数可测，无随机判局；
4. **确定性契约**：AI 失误、棋谱生成全部走确定性种子；同种子 + 同输入序列逐帧一致，支持自动化验证；≥1000 步随机走子游走（状态机不崩、走法合法、棋子数守恒、无非法杀棋）。

### 3.5 操作与手感（键鼠触全通 + 输入缓冲）
- **桌面鼠标（主路径）**：
  - **走子**：点击己方棋子 = 选中（高亮合法落点柔光），点击合法落点 = 走子；点击另一己方子 = 换选；Input Buffer：落子 60ms 窗口接受，连点不吞指令；
  - **拖放**：按住棋子拖到合法落点松手 = 走子（拖放与点选双通道）；
  - **悔棋**：`Ctrl+Z` 或点击棋盒"悔棋"（对战模式限 3 次/局，残局模式禁用）；右键 = 取消选中；
- **键盘**：`↑↓←→`（或 `WASD`）移动光标选子，`空格`/`Enter` = 确认选中/走子，`U` = 悔棋，`1/2/3/4/5` = 快捷选 AI 档位，`Esc` = 取消/暂停/退回弹层；
- **移动端（触控）**：点击选子、点击合法落点走子（非法落点轻震回弹）；底部预留 `padding-bottom: max(68px, calc(16px + env(safe-area-inset-bottom)))` 广告安全避让区，绝不遮挡走子区；
- **手感调优**：落子"笃"（木质低响）、吃子"啪"（双段）、将军"叮"（警示铃）；选中与合法落点用无边界径向柔光（禁硬边描边圈）；杀棋瞬间慢镜 + 木桌共鸣 + 棋子微震。

## 4 · 题材原生视窗隐喻与音色质感（拒绝抄袭雷同）

### 4.1 题材风格关键词
**红木棋桌对弈局（Redwood Chess Table）**、红木/乌木浮雕棋子、楚河汉界、纸质记分簿、木制棋盒、泛黄棋谱卡、茶室暖光、茶烟微尘。

### 4.2 专属视窗物理隐喻（严禁左右双翼模版）
本作不是"网页里嵌个棋盘"，而是一方**红木棋桌上的对弈局**：

1. **棋桌即全部**：对弈是红木棋桌上的一局——纸质记分簿、泛黄棋谱卡、木制棋盒、选关/悔棋收纳于桌边挂件与棋盒托盘，**绝无四角散落浮动按钮、绝无右侧白底 SaaS 卡片堆**；
2. **浮雕棋子质感**：红木/乌木浮雕圆棋（实体微浮雕 + 按下位移），选中与合法落点用**无边界径向柔光**（禁硬边描边圈）；

4. **环境氛围**：茶室暖光 + 茶烟微尘粒子，拒绝死黑/死白大平铺；返回、音效、语言轨收纳进棋桌顶框一体化状态条；
5. **移动端（≤768px）**：棋盘全宽撑满、棋盒操作条收折为桌下木质工具条，底部严格预留广告安全避让区，绝不遮挡走子区。

### 4.3 立体质感与渲染路线裁决
- **裁决：纯 Canvas 2D 棋盘舞台 + DOM/CSS 3D 红木棋桌框体**（不做 Three.js）：
  - 棋盘、棋子（浮雕圆棋 + 径向光影）、走子高亮、吃子粒子 → Canvas 2D，120fps 秒开零发热；
  - 棋桌立体感（红木厚度、纸质记分簿、木制棋盒、茶室光晕）→ 语义 DOM + CSS 3D（`perspective` / `transform`），HUD/记分/弹层全部严格留在 DOM 层；
  - 理由：9×10 棋盘为平面二维结构，俯视 2D 即可完整表达，无真 3D 视角需求，Three.js 无必要。

### 4.4 声效风格与材质音色规划（WebAudio 纯程序化合成，零外部音频文件）
| # | 事件 | 材质音色方案 | 合成手法 |

| 2 | **吃子（Capture）** | 提子轻响 + 吃子重落"啪"双段 | 双段噪声脉冲（提 + 落），低频加重 |

### 4.5 封面设计提案（遵循 `docs/COVER-STYLE.md`）
- **尺寸与格式**：640×640 纯 WebP，**零文字**；
- **主体构图**：单一居中主体，占画面 65%~70%——**两枚 3D 软胶木纹圆棋**（一枚红木色、一枚乌木色，表面为柔润木纹无文字）在红木棋盘格上迎面而立，一枚微倾似将落子，棋盘边角露出"楚河汉界"意象的浅刻线（无文字）；

## 5 · 制作人拍板与开放探讨

请制作人（用户）对以下 3 个核心玩法设计进行拍板定夺：

### 拍板项 1：模式配比？
- **选项 A（残局闯关 + 阶梯 AI + 双人三轨 · 推荐）**：残局闯关（4 章 × 6 关 = 24 关）为成长线，阶梯 AI 对战与同屏双人对弈为附加——解题成长、实力挑战、派对博弈三种乐趣齐备；
- **选项 B（残局闯关 + 阶梯 AI 双轨）**：只做残局闯关与阶梯 AI 对战，最聚焦、开发量适中；
- **选项 C（纯残局闯关）**：只做残局解题，最轻量（求解器校验体系最完整）。

### 拍板项 2：残局编排深度？
- **选项 A（杀法类型章节制 · 推荐）**：双车错 → 马后炮 → 车马冷着 → 经典名局，每章先教一种杀法再考一组残局——"学杀法 → 用杀法"成长闭环；
- **选项 B（难度阶梯制）**：不按杀法类型，只按难度（入门残局 → 大师残局）编排，更纯粹；
- **选项 C（名局优先）**：直接上传统经典名局残局（七星聚会等改编简化版），情怀最足、制作最简。

### 拍板项 3：阶梯 AI 的强度上限？
- **选项 A（大师 = 深度 3 + 零失误 · 推荐）**：最高档零失误但深度受限，人类高手存在合理胜机，不会劝退；
- **选项 B（大师 = 深度 4 + 零失误）**：更高强度、更接近完美，对高手更有挑战；
- **选项 C（五档同深度、只调失误率）**：全部 depth2，仅失误率区分——实现最简，梯度靠失误率体现。
