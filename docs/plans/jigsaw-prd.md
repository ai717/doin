## 0・一页纸摘要



* **游戏名**：拼图（中）/ Jigsaw（英）/slug 首选 `jigsaw`（候选 `picture-puzzle`、`piece-together`）

* **一句话玩法**：每关一张独特的抽象艺术图被切成 N×N 碎片打乱，拖动碎片交换位置，复原完整图案。

* **一句话差异化**：Poki 上的拼图全靠 Barbie/Talking Tom 等 IP 授权、JigZone 靠海量照片图库；DOIN 这版用**程序化生成的抽象艺术图**—— 每关一张独特壁纸、零版权、拼完本身就是审美享受，且和门户其他游戏一样轻量无加载负担。

* **目标玩家 / 场景**：25–40 岁喜欢视觉治愈、不追求硬核烧脑的放松玩家，3–8 分钟一局，通勤 / 睡前 / 摸鱼。

* **首发模式**：5 章 × 10 关 = 50 关（3×3 → 4×4 → 5×5）+ 每日精选。

* **技术路线**：plain 静态、Canvas 渲染、零外链图库（图由代码生成）。

* **预估工期**：5–7 人日。

## 1・市场与竞品调研（产品线负责人视角）

**品类判断**：数字拼图是 web 端长青品类（JigZone 运营近 20 年、Arkadium 每日拼图常年在榜），用户心智成熟、无学习成本。DOIN 14 款游戏里没有拼图 —— 益智区缺一块 "视觉系放松"。



| 对标                            | 平台            | 核心机制                  | 亮点               | 可借鉴                     | 要避开             |
| ----------------------------- | ------------- | --------------------- | ---------------- | ----------------------- | --------------- |
| Brainrot Puzzle               | Poki          | 全碎片打乱、拖一块到另一块上交换位置    | 操作极简，网红梗图 IP     | "交换模式" 交互（不是拖到空位），上手零学习 | 靠梗图 IP，我们没有     |
| London Jigsaw / Barbie Jigsaw | Poki/MarketJS | 城市地标 / IP 角色照片，拖拽吸附   | 多难度件数选择          | 难度分级、吸附 "snap" 反馈       | 版权图我们用不起        |
| The Daily Jigsaw（Arkadium）    | Web           | 每日一张图 + 计时 + 高分       | 每日留存钩子           | 每日挑战模式、计时器              | 重型平台 UI 复杂      |
| Jigsaw Explorer               | Web           | 边缘碎片分组、连接成块整体移动       | 真 jigsaw 锯齿 + 托盘 | "对了自动锁、错了不粘" 的安全设计      | 锯齿块工程量大，v1.1 再做 |
| Favorite Puzzles（Playgama）    | Web           | 库存图 + AI 生成图 + 用户自己照片 | 内容源多元            | "拼完一张解锁下一张" 的节奏         | AI 生成图在纯静态站做不到  |

**差异化定位陈述**：*当玩家想安静拼点东西放松、又不想看 IP 授权卡通图、不想下 App 时，DOIN 拼图是网页端唯一 "每关一张独特抽象艺术图、碎片交换即玩、拼完像收一张壁纸" 的轻量拼图。*

**与门户现有游戏关系**：



* tag 补 `益智 / 视觉 / 每日挑战`；与 Tile-Matching（三消交换）共享 "交换" 操作但目标不同（三消求消除，拼图求复原）；与 one-line（一笔画）同属 "轻度视觉益智" 但节奏更慢更放松。

* 与 klotski/orbit-sort 的硬核烧脑形成互补 —— 拼图是 "放空大脑" 的品类，HUD 不催时间。

## 2・产品定位与范围（PM 视角）

**核心循环（一局 3–8 分钟）**：



```
看到一张打乱的抽象艺术图 → 拖动碎片交换 → 越拼越完整 → 全对自动锁定

&#x20;  ↑\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_↓

&#x20;  卡住？ → 长按看原图 2 秒 / 重排一次
```

**玩家画像**：不是硬核解谜玩家（那是 klotski/sudoku 用户），而是 "想让手和眼睛有点事做、脑子放空" 的人。对他们来说时间压力是负资产 —— 时间分权重压到最低。

**MVP（首发必须有）**：



1. 50 关，5 章 × 10 关，从 3×3（9 块）到 5×5（25 块）。

2. **交换模式**：所有碎片初始在棋盘上乱序，拖一块放到另一块上交换位置。

3. **自动吸附锁定**：碎片拖到正确位置（网格对齐 + 图片内容匹配）时 "咔" 一声锁定，锁定后不可再拖。

4. **幽灵原图**：长按 "原图" 按钮显示完整图 2 秒，松手回游戏。

5. **重排**：每关 3 次 "重排" 机会（所有未锁定碎片重新乱序，已锁定不动）。

6. HUD：步数（交换次数）/par/ 实时预估分 / 总积分。

7. 每日精选：按日期 hash 选一关。

8. 本地进度、中英 i18n、WebAudio 音效、静音、`prefers-reduced-motion` 降级。

**v1.1+ 后置（明确不做）**：



* 真 jigsaw 锯齿异形块 —— 需自绘锯齿路径 + 碰撞合并，工程量翻倍。

* 旋转碎片模式 —— 增加操作复杂度，先把交换做爽。

* 上传用户照片拼图 —— 纯静态站无图片上传服务，外链图又违反零外链规则。

* 托盘区 / 边缘分组 / 缩放 —— 重型拼图平台功能，DOIN 定位轻量。

* 6×6 以上高难度 ——5×5（25 块）已足够 8 分钟一局。

**绝对不做**：联机、账号、内购、广告、排行榜全站。

## 3・玩法设计（游戏设计大师视角）

### 3.1 规则定义（引擎规格）

**棋盘**：每关一个 `N×N` 网格，`N ∈ {3,4,5}`。棋盘是正方形，每格放一块碎片。碎片是完整艺术图的一个矩形切片。

**完整图生成**：每关由种子 `seed` 程序化生成一张正方形艺术图（Canvas 绘制，512×512）。生成规则：



* 底层：柔和双色渐变背景。

* 中层：3–6 个半透明圆形 / 多边形，位置 / 大小 / 色相由 `seed` 经 PRNG（mulberry32）决定。

* 上层：2–4 条柔和弧线 / 噪点纹理。

* 生成结果**完全确定**：同 seed 永远生成同一张图（测试可复现）。

**碎片表示**：



```
// 状态：grid\[i]\[j] = 碎片在棋盘上的"原位置" (r, c)

// 即 grid\[i]\[j] 上现在放着原本属于 (r,c) 的那块

state = {

&#x20; n,                 // 3/4/5

&#x20; grid: \[\[{r,c}, ...], ...],  // n×n，值是该块的原始坐标

&#x20; locked: \[\[bool, ...], ...],  // n×n，是否已锁定

&#x20; moves: 0,

}
```

**操作意图**：`{ type: "swap", from: {i,j}, to: {i,j} }`。`applyMove(state, intent)` 返回 `{ state, action }`。

**移动规则**：



1. 若 `from` 或 `to` 已锁定 → `action = null`（不能拖动已锁定块）。

2. 交换 `grid[from]` 与 `grid[to]`。

3. 交换后检查两块是否 "到位"：`grid[cell] === cell`（该位置现在放着属于这里的块）。到位则 `locked[cell] = true`，播放锁定音。

4. `moves += 1`，`action = "swap"`。

**胜利判定**：`isSolved(state)` = 所有格子 `grid[cell] === cell` 且全部 locked。这是唯一终止态。

**纯函数签名（engine.mjs）**：



```
generateArtwork(seed) -> HTMLCanvasElement   // 纯生成，不碰 DOM 布局

createState(n, seed, rng) -> State           // rng 注入打乱

applyMove(state, swap) -> { state, action: "swap" | null }

isSolved(state) -> boolean

shuffle(state, rng) -> State                  // 重排未锁定碎片
```

**"合法操作永不报错" 落地**：



* 拖已锁定块 → `action = null`，给 60ms 轻抖动反馈。

* 拖自己到自己（from === to）→ `action = null`。

* 已通关后继续拖 → no-op。

* 所有 `action === null` 都不弹错误 toast。

### 3.2 创新点（体验层差异化）

不改 "交换碎片复原" 这个经典模型。差异化在三个体验层：



1. **程序化抽象艺术图（核心差异）**：不打包照片 / IP，每关一张独特的 "壁纸级" 抽象画。

* **为什么**：DOIN 零版权、零外链、目录轻量；拼完本身就是审美愉悦，玩家会觉得 "这张图好看"。

* **工程建模**：`generateArtwork(seed)` 纯函数，mulberry32 PRNG，512×512 Canvas，确定性生成。

* **反例**：Poki 上拼图全是 IP 卡通脸或写实照片，视觉上反而吵闹；我们走 "柔和渐变 + 几何" 的极简现代风。

1. **"拼完即锁" 的安全设计**：碎片只有在正确位置才锁定，错误位置滑回去 —— 玩家永远不会 "把碎片放错卡死"，参考 Jigsaw Explorer 的安全设计。

2. **重排而非撤销**：不做无限 undo（拼图交换步数少，undo 意义不大）；改为 3 次 "重排" 机会，把未锁定碎片重新洗牌。这更符合 "卡壳了换个视角" 的心智。

**为什么不做锯齿 jigsaw / 旋转碎片**：那是重型拼图平台的事；我们的定位是 "3 分钟放松拼图"，方格交换足够。留 v1.1。

### 3.3 难度曲线与内容



| 章    | 主题  | 碎片数 | 图风格        | 目标 par（交换次数） |
| ---- | --- | --- | ---------- | ------------ |
| 1 初窥 | 3×3 | 9   | 高对比渐变（易辨认） | 3–8          |
| 2 几何 | 3×3 | 9   | 带几何形状      | 6–14         |
| 3 进阶 | 4×4 | 16  | 柔和渐变       | 12–30        |
| 4 层次 | 4×4 | 16  | 多图层        | 25–50        |
| 5 大师 | 5×5 | 25  | 细腻纹理       | 40–90        |

**par 来源**：不跑 BFS（拼图交换最优解状态空间大且玩家不需要知道理论最优），par 用**经验公式**：`par = n·n + n`（如 3×3=12、4×4=20、5×5=30），再在测试时用固定种子让一个人类 / 贪心算法试解 10 次取中位数校准。这个 par 是 "休闲玩家正常发挥就能接近" 的线，不是数学最优。

**关卡 seed**：50 个固定 seed 写死在 `levels.mjs`，每个 seed 对应一张独特艺术图。同 seed 永远同图，保证可复现和测试。

**每日精选**：`dailySeed = hash(todayKey()) % 50`，同日期全服同一张图。每日通关额外 +150 基础分（对齐 orbit-sort 量级）。

## 4・数值框架（数值策划视角）

**计分公式**（与 klotski 整站对齐，满分 800）：



```
total = base(200) + move(max 500) + time(max 100)
```



* **base = 200**：固定，通关即得。

* **moveScore(moves, par)**：


  * `moves ≤ par` → 500。

  * `par < moves ≤ par·2` → `500 - 5·(moves - par)`。

  * `moves > par·2` → 保底 100。

* **timeScore(elapsedSec, par)**：


  * `targetSec = 60 + par·2`（拼图不催时间，比 klotski 宽松一倍）。

  * 超时每 10 秒 -2，保底 20。

* **perfectScore = 800**。

**三个算例**：



| 关   | n | par | 玩家表现       | base | move         | time                            | total   |
| --- | - | --- | ---------- | ---- | ------------ | ------------------------------- | ------- |
| L1  | 3 | 12  | 8 步、40 秒   | 200  | 500          | 100                             | **800** |
| L25 | 4 | 20  | 35 步、180 秒 | 200  | 500-5·15=425 | target=100s，超时 80s → 100-8・2=84 | **709** |
| L50 | 5 | 30  | 75 步、400 秒 | 200  | >par·2 → 100 | target=120s，超时 280s → 保底 20     | **320** |

**步数统计**：每次真实 `action === "swap"` 才 +1；重排不计步（它是工具不是解）。

**存档结构**（`doin.jigsaw.v1`）：



```
{

&#x20; version: 1,

&#x20; prefs: { muted: false, reducedMotion: false },

&#x20; unlocked: 5,

&#x20; current: { levelId: 0, state: null },

&#x20; levels: { "\<id>": { cleared, bestScore, bestMoves, bestTimeMs } },

&#x20; daily: { dateKey, bestScore }

}
```

损坏字段 normalize 回默认，绝不白屏。

## 5・UX 设计（UX 负责人视角）

**操作模型**：



* 桌面：鼠标按住碎片拖到另一块上松手 → 交换。点击选择一块再点目标也可。

* 触屏：手指按住拖碎片到目标格松手。

* 不做 "点哪块自动飞到哪"—— 拖放本身就是手感的一部分。

**反馈通路**：



| 事件          | 视觉                   | 听觉      | 触感      |
| ----------- | -------------------- | ------- | ------- |
| 开始拖动        | 碎片放大 1.05 倍 + 阴影     | 无       | —       |
| 交换          | 两块补间滑动交换位置           | 轻 "咻" 声 | —       |
| 锁定到位        | 碎片淡入一层细描边 + 120ms 脉冲 | "咔" 定位音 | 10ms 震动 |
| 拖错（放手在非目标格） | 碎片滑回原位               | 无       | —       |
| 重排          | 所有未锁定块旋转散落动画         | 洗牌音     | —       |
| 通关          | 全图淡入 + 金色边框脉冲        | 五声音阶上行  | 25ms    |
| 破纪录         | 分数 bump              | 高音叮     | 20ms    |

**新手引导**：第 1 关 3×3，开场 3 秒在第一对该交换的碎片上画虚线箭头。不做弹窗教程。

**信息层级**：



* 顶栏：返回 ← 第 X/50・步数 8/par 12・得分 720/800 → 静音

* 底栏：原图（长按）/ 重排（剩余 3 次）/ 重选关

**无障碍**：



* `prefers-reduced-motion`：交换 / 重排动画关闭，直接跳格。

* 色盲：图案不依赖单一色相（每关多色 + 明暗对比），锁定用 "细描边" 而非纯红色。

* 触屏拖拽阈值 10px 防误触。

* 隐私模式 localStorage 不可用 → 静默降级内存。

## 7・技术方案（开发负责人视角）

**路线**：plain 静态。

**模块清单**：



| 文件               | 职责                                                          |
| ---------------- | ----------------------------------------------------------- |
| `index.html`     | 标记 only                                                     |
| `favicon.svg`    | 拼图块简笔                                                       |
| `css/style.css`  | 布局、双栏、移动、reduced-motion                                     |
| `js/engine.mjs`  | 纯函数：`createState/applyMove/isSolved/shuffle`，DOM-free       |
| `js/artwork.mjs` | `mulberry32(seed)` + `generateArtwork(seed)` → canvas，确定性生成 |
| `js/levels.mjs`  | 50 个 seed + par 表 + 每日 hash                                 |
| `js/game.mjs`    | DOM-free：步数、计时、重排次数、通关判定                                    |
| `js/render.mjs`  | Canvas：绘制棋盘 + 碎片切片 + 拖拽 + 补间动画 + DPR                        |
| `js/ui.mjs`      | HUD、选关页、弹窗、按钮                                               |
| `js/score.mjs`   | 计分唯一口径                                                      |
| `js/storage.mjs` | 存档 `doin.jigsaw.v1`                                         |
| `js/i18n.mjs`    | 中英双表                                                        |
| `js/audio.mjs`   | WebAudio 合成：swap/lock/win/reshuffle                         |
| `js/main.mjs`    | 装配                                                          |

**三条铁律**：



1. `applyMove` 合法交换必执行；拖已锁定块 / 同格交换返回 `action: null`，不抛错。

2. UI 只发 `{from,to}` 意图，不直接改 grid；Canvas 从 engine state 重绘。

3. localStorage 读取全 normalize，坏值回默认；不可用降级 Map。

**渲染**：Canvas 2D。一张 512×512 艺术图离屏 canvas，每格绘制对应切片（`drawImage` 源矩形）；拖拽用 pointer events，拖动中的碎片画在最上层并轻微放大。补间 120ms ease-out；reduced-motion 直接跳。

**音频事件**：swap（轻咻）、lock（咔）、reshuffle（洗牌）、win（五声音阶）、newBest（叮）。AudioContext 首次手势解锁。

**i18n 键骨架**：



| key           | 中    | 英       |
| ------------- | ---- | ------- |
| app.title     | 拼图   | Jigsaw  |
| hud.moves     | 步数   | Moves   |
| hud.par       | 标准   | Par     |
| hud.score     | 得分   | Score   |
| btn.preview   | 原图   | Preview |
| btn.reshuffle | 重排   | Shuffle |
| win.title     | 完成！  | Solved! |
| daily.title   | 今日拼图 | Daily   |
| nav.back      | 返回首页 | Home    |

**测试四类**：



1. `engine.test.mjs`：交换规则、锁定判定、isSolved、拖已锁定块返回 null、打乱可解性（50 关每关跑随机交换直到 solved，验证不卡死）。

2. `artwork.test.mjs`：同 seed 生成结果像素一致（取哈希对比）；不同 seed 结果不同。

## 8・风险与开放问题

**Top 3 风险**：



1. **程序化图案不够 "好看"**：几何渐变太抽象，玩家觉得不像 "图片"。

* 缓解：前 10 个 seed 在设计时人工调参（参考成熟生成艺术如 "Generative Art" 的柔和配色），拼出来像手机壁纸；不满意就迭代 artwork 生成器加纹理 / 噪点层。

1. **交换模式比 "拖到空位" 难上手**：玩家可能不知道要 "两块交换"。

* 缓解：第 1 关虚线箭头明确指示 "拖这块到那块"；UI 文案写 "拖动碎片到另一块上交换"。

1. **5×5（25 块）太碎、图案难辨**：抽象图切片后没有明显特征，玩家只能乱试。

* 缓解：大师章（第 5 章）的图案增加高对比大色块，确保即使切片也有可辨识的视觉锚点。

**待用户拍板**：



1. **slug**：`jigsaw`（首选，搜索量大）/ `picture-puzzle`（更准确）/ `art-pieces`？

2. **玩法模型**：交换模式（拖一块到另一块上换位置）vs 空位吸附（碎片从托盘拖到空格里）？推荐交换 —— 和 Brainrot Puzzle 一致，操作更顺。

3. **是否要 "旋转碎片"**（每块需要转到正确方向）？推荐不要，先把交换做爽。
